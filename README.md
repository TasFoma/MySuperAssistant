# MySuperAssistant

Личный ассистент для ПК и смартфона на C++20 и Qt6: чат, память, дневник,
планировщик, маршруты и погода. Сервер хранит общие данные, клиенты показывают их.
Геймификация запланирована после переноса.

Сейчас `msa_server` связывает TCP-протокол версии 1, SQLite и предметные сервисы:
задачи, события, напоминания, привычки, беседы, профиль и дневник. Чат использует
HTTP llama-server, явный поиск — SearXNG; геокодинг — Nominatim, маршруты — OSRM,
погода — Open-Meteo. Приветствия и вечерний опрос сохраняются в постоянном чате
«Основной». Текстовые команды выполняются с атомарной записью результата и истории.

Настоящие модели и внешние сервисы в этой связке ещё не проверены. Качество
ментора, выделения фактов и памяти требует отдельной проверки. Контекст ограничен
кодовыми точками Unicode; точного контроля токенов пока нет.
`msa_desktop` открывает окно с чатом, планами, напоминаниями, настройками и
локальной музыкой. `msa_mobile` пока запускает цикл QGuiApplication без окна.
На ПК добавлен [голосовой ввод Vosk на C++](docs/modules/SpeechRecognizer.md).
Озвучка сообщений доступна через Qt TextToSpeech; мобильные уведомления ещё не подключены.

В `infra` готов асинхронный [TcpClient](docs/modules/TcpClient.md): auth/get_all,
ответы и события, автоматическое восстановление максимум за пять попыток на цикл.
После исчерпания попыток он ждёт ручного переподключения; локальные функции
приложения могут продолжать работать. Отправленные записи после обрыва не повторяются.
Общие C++-модели для QML и проверяемая связка с транспортом готовы:
[ClientModels](docs/modules/ClientModels.md). Они сохраняют последние данные без
связи, показывают их устарелость и запрещают серверные действия до восстановления.
JSON разбирается в infra, UI получает типы core; контроллер находится в apps/desktop.
Готова [библиотека QML-компонентов](docs/modules/CommonQml.md): тёмная тема,
кнопки, поля, карточки, задачи, сообщения и состояния, включая переподключение.
Готов первый набор [экранов ПК и настроек](docs/modules/DesktopScreens.md):
чат, планы, напоминания и локальный JSON подключения. [Формы планировщика](docs/modules/PlannerEditor.md)
создают/изменяют задачи и события, создают/отмечают привычки, создают три вида
напоминаний и подтверждают удаление. [DesktopRuntime](docs/modules/DesktopRuntime.md)
загружает настройки, создаёт сетевую сессию по auto_connect и соединяет её с окном.
Без корректных настроек открывается форма без сетевых попыток. «Сохранить» только
записывает параметры; «Подключиться» и переподключение применяют сохранённый набор.

Подключён [локальный музыкальный плеер](docs/modules/MusicPlayer.md):
выбор папки, перемешанная очередь, пауза, переходы и громкость. Нижняя панель
работает во всех разделах независимо от сервера; music.settings.json хранит
папку и громкость отдельно от сетевых параметров. Восстановление не запускает
звук; после полного прохода битых файлов плеер ждёт явного действия.
Окно и плеер создаются в main, закрытие приложения завершает сеть и аудио.

## Структура исходников

Заголовки C++ находятся в include, реализации — в соседнем src, включая код
приложений и тестовых помощников. Например, desktop использует
`src/apps/desktop/include/msa/desktop/` и `src/apps/desktop/src/`.
В `src/ui/common/` и `src/ui/desktop/` модели находятся в `Model/include` и
`Model/src`, QML — в `UI`. Повторно используемая вёрстка — в `UI/Utils`.
Внутренние помощники core имеют заголовки в `include/msa/core/detail/`;
тесты используют `tests/<набор>/src` и `tests/<набор>/include`.
Правила новых файлов и групп модулей закреплены в [AGENTS.md](AGENTS.md).

## Подготовка Android

Для установленного Qt 6.10.3 Android нужны JDK 17, Android SDK Platform 36,
Build Tools 36.0.0, Platform Tools и NDK 27.2.12479018. Версию NDK подтверждает
`modules/Core.json` Android-кита. Минимум — Android 9 (API 28), только arm64-v8a,
без эмулятора (решение 59). Общие пресеты android-debug/android-release используют
Ninja, личные пути задаются в CMakeUserPresets.json; шаблон содержит оба
android-debug-local/android-release-local вместе с Windows-пресетами.

На текущем ПК инструменты установлены в `%LOCALAPPDATA%/Android/Sdk` и
`%LOCALAPPDATA%/Android/Java/jdk-17.0.21+9`. Пути сохранены штатным `sdktool`
в Android-настройках Qt Creator; для их применения перезапустите Creator.
Глобальные JAVA_HOME и PATH не менялись, существующий JDK 25 сохранён.

После включения USB-отладки и подтверждения доверия компьютеру на телефоне:

```powershell
& "$env:LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe" devices -l
```

Статус `device` означает готовность ADB; при `unauthorized` нужно подтвердить
запрос на телефоне. Samsung A55 проверен через ADB: Android 16/API 36, arm64-v8a.

Команды из корня для Android Debug и Release:

```powershell
cmake --preset android-debug-local
cmake --build --preset android-debug-local
cmake --preset android-release-local
cmake --build --preset android-release-local
```

Android Debug сконфигурирован и собран, включая APK:
`out/build/android-debug-local/src/apps/mobile/android-build/build/outputs/apk/debug/android-build-debug.apk`.
AAPT2 подтвердил minSdkVersion=28, targetSdkVersion=36 и arm64-v8a.
Release-пресет подготовлен, но ещё не проверен сборкой. Установка и запуск
на телефоне пока не проверены; мобильное приложение ещё не создаёт окно.

## Сборка Windows Debug

Требуются CMake 3.25+, Visual Studio 2022 с MSVC x64, Git, Qt 6.10+ с Gui,
Quick, Sql, Network, Multimedia, TextToSpeech, Qt Quick Dialogs и драйвером QSQLITE. Шаблон использует Qt 6.10.3:
`C:/Qt/6.10.3/msvc2022_64`.

1. Если личного пресета ещё нет, создайте его и проверьте CMAKE_PREFIX_PATH:

   ```powershell
   Copy-Item CMakeUserPresets.json.example CMakeUserPresets.json
   ```

2. Из корня выполните:

   ```powershell
   cmake --preset windows-debug-local
   cmake --build --preset windows-debug-local
   ctest --test-dir out/build/windows-debug-local -C Debug --output-on-failure
   ```

Результат — Debug-сборка в `out/build/windows-debug-local` и зелёные тесты.
FetchContent загружает закреплённые PCRE2 10.47 и GoogleTest v1.18.0 с GitHub;
сеть может требоваться и при повторной конфигурации.
На Windows также загружается пакет Vosk 0.3.45 x64 с проверкой SHA256; его DLL
использует только служебный C++-процесс распознавания, а не сервер.
Visual Studio многоконфигурационная: Debug задаётся build-пресетом и флагом CTest.

`msa_core_tests` проверяет предметные правила с управляемыми часами и хранилищами
в памяти. `msa_infra_tests` проверяет SQLite, HTTP/JSON, TCP и связку сервера на
временных базах и локальных сокетах, включая напоминания во время HTTP-запроса.
Настоящая сеть и модель для тестов не нужны. CTest добавляет каталог Qt в PATH
для infra-тестов. Android-пресеты описаны выше; тестовые цели пока только для ПК.

Музыкальные тесты используют временные папки, повреждённые файлы и беззвучный
WAV с нулевой громкостью, а не личную медиатеку. Они проверяют реальный Qt backend,
остановку после ошибок и восстановление параметров без автозапуска.

Часть infra-тестов автоматически запускает настоящий `msa_server` отдельным
процессом с временными настройками и базой. Независимый тестовый TCP/JSON-клиент
проверяет потерянное подтверждение записи, завершение LLM после обрыва,
переподключение/перезапуск и явный повтор без второго User. Локальная HTTP-модель
позволяет управлять моментом ответа; личные настройки не используются.
Подробнее — [ProtocolTestClient](docs/modules/ProtocolTestClient.md).

Те же infra-тесты проверяют клиентские декодеры, модели и их связку с сервером.
Невизуальный QQmlComponent проверяет свойства и обновление bindings без окна.

`msa_ui_tests` загружает общие QML-компоненты через статический плагин и проверяет
ввод, клавиатурную активацию, подтверждение задачи, переподключение и узкую ширину.
CTest задаёт offscreen и программный рендеринг: видимое окно не открывается.
На Windows offscreen получает системные шрифты из WINDIR/Fonts.
Тест галереи сохраняет `out/build/windows-debug-local/common-components-preview.png`.
Тесты экранов сохраняют рядом `desktop-screen-0.png` … `desktop-screen-3.png`.
Настройки проверяются на временных файлах; личные параметры не читаются.

## Запуск клиента ПК

Из корня проекта после сборки:

```powershell
$env:PATH = "C:/Qt/6.10.3/msvc2022_64/bin;$env:PATH"
& ./out/build/windows-debug-local/Debug/msa_desktop.exe
```

Откроется окно. При первом запуске в настройках заполните host, port и token
вашего сервера, нажмите «Сохранить», затем «Подключиться». Переключатель
«Подключаться при запуске» действует при следующем запуске; выключите его,
чтобы слушать локальную музыку без автоматических попыток. После пяти неудач
нужно явное переподключение. Закрытие последнего окна завершает клиент;
работы в трее пока нет.

Стандартные файлы — client.settings.json и music.settings.json в
QStandardPaths::AppConfigLocation для организации MySuperAssistant и приложения
msa_desktop. Нужный файл можно передать явно, независимо для сети и музыки:

```powershell
& ./out/build/windows-debug-local/Debug/msa_desktop.exe --config ./client.settings.json --music-config ./music.settings.json
```

Шаблоны — client.settings.json.example и music.settings.json.example. Реальные
параметры в git не добавляйте. Повреждённые файлы сами не перезаписываются.
Изменение адреса/токена применяется явным подключением и очищает кэш прежнего
сервера; обычный обрыв сохраняет последние строки с признаком устаревания.

`DesktopRuntimeTest.cpp` проверяет окно offscreen, включая настоящий процесс
сервера с временной SQLite-базой и отдельный процесс msa_desktop. Внешние сервисы,
личные параметры и видимые пользовательские окна тестам не нужны. Рендеры рядом
с остальными: desktop-startup-preview.png, desktop-startup-invalid-preview.png,
desktop-runtime-preview.png. Проверку на личном сервере и слышимого звука
пользователь выполняет отдельно; настоящая LLM в этих проверках не участвует.

## Голосовой ввод на ПК

В настройках выберите папку распакованной [модели Vosk](https://alphacephei.com/vosk/models).
Можно использовать уже имеющуюся модель старого клиента. Путь сохраняется отдельно
в voice.settings.json рядом с настройками подключения. Python не нужен.

В чате нажмите «Говорить». Первая запись загрузит модель; затем можно произнести
одну фразу или нажать «Завершить запись». Текст допишется в черновик; отправка
выполняется кнопкой «Отправить». «Отменить запись» отбрасывает незавершённую фразу.
Микрофон выключен до явного действия, работа с черновиком доступна без сервера.
Запись ограничена 30 секундами, ошибки не запускают её повторно.

В настройках раздел «Звук и голосовой ввод» позволяет выбрать микрофон и вывод
для музыки/озвучки. «По умолчанию» следует выбору Windows; имена устройств видны
в списках. Выбор сохраняется сразу в отдельном audio.settings.json рядом с
настройками клиента. «Обновить устройства» не включает микрофон.

Во время записи рядом с кнопками двигается индикатор уровня. Если он остаётся
нулевым, проверьте выбранный вход, аппаратное выключение микрофона и разрешение
Windows на доступ к микрофону для классических приложений. Если уровень меняется,
а текста нет, проверьте язык/папку модели и попробуйте отчётливо произнести фразу.
Пустой результат теперь сопровождается сообщением, а не тихим возвратом к готовности.
Настройки и ограничения — [AudioDevices](docs/modules/AudioDevices.md).

Автотесты проверяют управление C++-процессами и интерфейс без включения микрофона.
Качество распознавания речи на личной модели и устройство ввода проверяются вручную.

У сообщения нажмите «Озвучить», для остановки — «Остановить речь» у поля ввода.
Новая фраза прерывает предыдущую; автоматического чтения ответов нет. Озвучка
доступна и для загруженных сообщений без сервера, модель Vosk для неё не нужна.
Начало диктовки останавливает речь; озвучка отменяет активную диктовку без текста.
Подробнее — [SpeechSynthesizer](docs/modules/SpeechSynthesizer.md).

Для ПК нужен полный Qt 6.10.3 MSVC 2022 64-bit с бинарными Qt Speech и Qt Multimedia.
Голос берётся из системы; наличие модуля Qt не гарантирует наличия русского голоса.
Слышимость и системные голоса проверяются вручную. Документация/примеры Speech
сами по себе не устанавливают бинарный модуль. Библиотеки разных версий Qt не смешиваются.

## Запуск сервера

1. Создайте личный файл из примера:

   ```powershell
   Copy-Item server.settings.json.example server.local.json
   ```

2. Замените все заглушки в server.local.json: адрес слушателя, токен, IANA-зону,
   endpoint сервисов, User-Agent с контактом, бюджет контекста и лимит генерации.
   Два числовых лимита задайте JSON-числами без кавычек. model можно оставить
   пустой строкой для выбора llama-server; api_key — пустой без Bearer.
   В SearXNG должен быть включён JSON API. database_path задаётся относительно
   каталога настроек либо абсолютным путём; его родительская папка должна существовать.
   Подробности — [сервер приложения](docs/modules/ServerRuntime.md).

3. В PowerShell из корня запустите сервер без окна:

   ```powershell
   $env:PATH = "C:\Qt\6.10.3\msvc2022_64\bin;$env:PATH"
   & .\out\build\windows-debug-local\Debug\msa_server.exe --config .\server.local.json
   ```

   Ожидается сообщение с TCP-портом, процесс продолжает работать. Ctrl+C завершает
   процесс. Если Qt установлен иначе, замените путь только в своей команде.
   Личный файл и файлы *.sqlite с журналами исключены через .gitignore.

База создаётся новой, без импорта старого проекта; текущая схема — версия 13.
При повторном запуске данные и ID основного чата сохраняются. Доступ к серверу
предполагается через Tailscale; собственного TLS нет. Новый клиент выполняет auth,
затем get_all и нужные операции по [протоколу](docs/protocol.md).
После потери ответа изменяющая операция не повторяется автоматически.
Пока выполняется внешний запрос, чтение и проверки сроков работают, новые
изменяющие операции получают busy. Уведомления не имеют очереди воспроизведения.
