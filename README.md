# MySuperAssistant

Личный ассистент для ПК и смартфона на C++20 и Qt6. Репозиторий содержит каркас
трёх приложений: сервера, Windows-клиента и Android-клиента.

Сейчас работают только библиотечные части: локальный разбор русских команд,
типы планировщика, интерфейсы часов и репозиториев и сервисы напоминаний по времени и месту, календаря дня/месяца, привычек, задач, создания/изменения событий, предупреждений о событиях и ежедневного приветствия. Для тестов есть часы
и репозитории в памяти. `UserProfileService` добавляет факты памяти без автоматического
удаления старых, с ручными тегами и признаком приоритета.
Полный профиль, источники и версии сохраняются на диске через
[SqliteUserProfileRepository](docs/modules/SqliteUserProfileRepository.md);
приложения хранилище пока не используют.
`UserProfileFactSelector` отбирает полные факты по словам вопроса в тексте и тегах;
сначала идут приоритетные, затем тематические по числу совпадений.
Автоматические предложения фактов из ответа LLM сохраняются с ID исходных чата
и сообщения, при наличии — записи дневника. Исправления создают новые версии,
старые остаются в профиле и исключаются из отбора; точные автоматические повторы
пропускаются. Качество выделения пока проверено только на заданных ответах тестового
клиента. Подробнее — [UserProfileService](docs/modules/UserProfileService.md).
`DailyContextService` формирует сводку дня: дата/время, события, пять открытых задач
и прогресс привычек. Готовую сводку можно передать сборщику контекста LLM.
`EveningCheckInService` подготавливает вечерний опрос один раз за день с 20:00;
в библиотеке ConversationService реализовано ожидание и обработка предложения
записи ответа; доставки клиентам пока нет.
`ReminderService` возвращает общий список активных напоминаний: сначала по ближайшему
сроку, затем по месту, включая записи без координат; при равенстве — по ID.
`MoodService` сохраняет явную оценку настроения и полный текст заметки; возвращает
историю за 14 календарных дней или другой период без удаления старых записей.
Есть хранилище дневника в памяти для тестов и
[SqliteMoodRepository](docs/modules/SqliteMoodRepository.md) для файла SQLite;
анализ настоящей моделью ещё не проверен. Подробнее — [MoodService](docs/modules/MoodService.md).
`ChatService` создаёт и переключает чаты, восстанавливает выбранный чат и сохраняет
полные сообщения пользователя и ассистента. Это библиотечные операции:
есть хранилище в памяти для тестов и SQLite-хранилище с восстановлением выбора
после повторного открытия файла. Подробнее — [ChatService](docs/modules/ChatService.md)
и [SqliteChatRepository](docs/modules/SqliteChatRepository.md).
Для будущего контекста LLM можно отдельно отобрать последние целые сообщения
по явному лимиту символов Unicode; полная история сохраняется.
`LlmContextBuilder` объединяет инструкции, текущий вопрос, заранее выбранные факты,
сводку дня и историю по общему лимиту текста без изменения исходных данных.
Отбор памяти пока буквальный, без синонимов и склонений; приложения его не вызывают.
Промпт ментора реализован, точной проверки токенов модели пока нет. Подробнее —
[UserProfileFactSelector](docs/modules/UserProfileFactSelector.md) и
[LlmContextBuilder](docs/modules/LlmContextBuilder.md).
`LlmClient` задаёт контракт полного ответа, отдельно возвращает тон и предложение
явной записи настроения; проверяет запрос и результат без автоматических повторов.
Заметка предложения заполняется исходным сообщением пользователя. Пока есть
только FakeLlmClient для тестов; HTTP и JSON-разбор не реализованы. Подробнее —
[LlmClient](docs/modules/LlmClient.md).
`ConversationService` связывает эти сервисы: сохраняет User, собирает контекст
с `MentorPrompt`, получает один полный ответ, выполняет явную запись через
`MoodService`, сохраняет факты/версии профиля и Assistant. Подтверждения записей
добавляет программа после успешного сохранения. Ожидание вечернего ответа привязано к чату
и дате; при ошибке LLM возможен явный повтор без дублирования User. Проверка пока
с тестовым клиентом, без настоящей модели. Общей транзакции между репозиториями
нет; повтор после технической ошибки записи небезопасен. Подробнее —
[ConversationService](docs/modules/ConversationService.md).
`SqliteDatabase` в infra открывает новую базу, проверяет принадлежность и версию,
атомарно применяет миграции и поддерживает вложенные транзакции. Базовая версия 1
не содержит предметных таблиц; список `sqliteMigrations()` добавляет версию 2
с чатами, сообщениями и текущим выбором, затем версию 3 с профилем и тегами
и версию 4 с датой последнего приветствия. Хранилище даты —
[SqliteGreetingRepository](docs/modules/SqliteGreetingRepository.md).
Версия 5 сохраняет дату вечернего опроса и ожидание ответа через
[SqliteEveningCheckInRepository](docs/modules/SqliteEveningCheckInRepository.md).
Версия 6 сохраняет отметки предупреждений о событиях через
[SqliteEventWarningRepository](docs/modules/SqliteEventWarningRepository.md).
Версия 7 добавляет дневник настроения и внешний ключ от факта профиля к записи дневника.
Версия 8 добавляет задачи через [SqliteTaskRepository](docs/modules/SqliteTaskRepository.md):
создание, чтение, изменение и удаление с сохранением полного текста и всех полей.
Версия 9 добавляет серии событий через
[SqliteEventRepository](docs/modules/SqliteEventRepository.md), включая повтор,
необязательное время и полное описание. Вхождения вычисляет CalendarService.
Версия 10 добавляет временные, повторяющиеся и геонапоминания через
[SqliteReminderRepository](docs/modules/SqliteReminderRepository.md), включая
статусы, следующий срок, интервал и необязательные координаты.
Начинаем с пустой базы без импорта старых
данных. Остальные SQLite-репозитории и общие транзакции операций чата ещё впереди.
Приложения базу пока не открывают. Подробнее —
[SqliteDatabase](docs/modules/SqliteDatabase.md).
Хранение остальных предметных данных на диске, сеть, чат с LLM, музыка, анализ настроения и подсказки ментора,
а также геймификация ещё не реализованы.

`msa_server` сразу завершается с кодом 0. `msa_desktop` и `msa_mobile`
создают `QGuiApplication` и запускают цикл событий, но не создают окна и не загружают QML.
Это пока не приложения, которыми можно пользоваться как ассистентом.

## Сборка Windows Debug

Требуются CMake 3.25 или новее, Visual Studio 2022 с компилятором MSVC для x64,
Git для загрузки зависимостей и Qt 6.10 или новее с компонентами Gui, Quick и Sql
и драйвером QSQLITE.
В шаблоне личных пресетов указан Qt 6.10.2: `C:/Qt/6.10.2/msvc2022_64`.

1. Если `CMakeUserPresets.json` ещё нет, создайте его из шаблона в корне репозитория:

   ```powershell
   Copy-Item CMakeUserPresets.json.example CMakeUserPresets.json
   ```

   При необходимости исправьте `CMAKE_PREFIX_PATH`. Личные пути хранятся в этом файле.

2. Из корня проекта выполните:

   ```powershell
   cmake --preset windows-debug-local
   cmake --build --preset windows-debug-local
   ctest --test-dir out/build/windows-debug-local -C Debug --output-on-failure
   ```

   Результат — Debug-сборка в `out/build/windows-debug-local` и успешный прогон тестов.
   Первая конфигурация загружает PCRE2 10.47 и GoogleTest v1.18.0 с GitHub через
   `FetchContent`, поэтому требует доступа к сети. Visual Studio — многоконфигурационный
   генератор: Debug задаётся build-пресетом, а для CTest — параметром `-C Debug`.

Предметные тесты собраны в `msa_core_tests` и регистрируются через `gtest_discover_tests`:
разбор команд, временные границы, типы планировщика, контракты репозиториев и фейковые часы.
Исходники находятся в `tests/core/`.

`msa_infra_tests` содержит файловые тесты SQLite из `tests/infra/`, зарегистрированные
через `gtest_add_tests`. Они создают QCoreApplication без окна и временные базы
в каталоге тестового запуска. На Windows CTest добавляет каталог Qt в PATH только
для этой группы тестов. Все проверки запускаются той же командой ctest выше.

Ветка сборки Android есть в CMake, но Android-пресетов в репозитории пока нет;
инструкции сборки и установки мобильного приложения ещё не подготовлены.
