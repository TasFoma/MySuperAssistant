# MySuperAssistant

Личный ассистент для ПК и смартфона на C++20 и Qt6: чат, память, дневник,
планировщик, маршруты и погода. Сервер хранит общие данные, клиенты показывают их.
Геймификация запланирована после переноса.

Сейчас `msa_server` связывает TCP-протокол версии 1, SQLite и предметные сервисы:
задачи, события, напоминания, привычки, беседы, профиль и дневник. Чат использует
HTTP llama-server, явный поиск — SearXNG; геокодинг — Nominatim, маршруты — OSRM,
погода — Open-Meteo. Приветствия и вечерний опрос сохраняются в постоянном чате
«Основной». Текстовые команды выполняются с атомарной записью результата и истории.

Настоящие модели и внешние сервисы в этой связке ещё не проверены. Качество
ментора, выделения фактов и памяти требует отдельной проверки. Контекст ограничен
кодовыми точками Unicode; точного контроля токенов пока нет.
`msa_desktop` и `msa_mobile` пока запускают цикл QGuiApplication без окна и QML.
Музыка, голос, мобильные уведомления и пользовательские экраны ещё не подключены.

## Сборка Windows Debug

Требуются CMake 3.25+, Visual Studio 2022 с MSVC x64, Git, Qt 6.10+ с Gui,
Quick, Sql, Network и драйвером QSQLITE. Шаблон использует Qt 6.10.2:
`C:/Qt/6.10.2/msvc2022_64`.

1. Если личного пресета ещё нет, создайте его и проверьте CMAKE_PREFIX_PATH:

   ```powershell
   Copy-Item CMakeUserPresets.json.example CMakeUserPresets.json
   ```

2. Из корня выполните:

   ```powershell
   cmake --preset windows-debug-local
   cmake --build --preset windows-debug-local
   ctest --test-dir out/build/windows-debug-local -C Debug --output-on-failure
   ```

Результат — Debug-сборка в `out/build/windows-debug-local` и зелёные тесты.
FetchContent загружает закреплённые PCRE2 10.47 и GoogleTest v1.18.0 с GitHub;
сеть может требоваться и при повторной конфигурации.
Visual Studio многоконфигурационная: Debug задаётся build-пресетом и флагом CTest.

`msa_core_tests` проверяет предметные правила с управляемыми часами и хранилищами
в памяти. `msa_infra_tests` проверяет SQLite, HTTP/JSON, TCP и связку сервера на
временных базах и локальных сокетах, включая напоминания во время HTTP-запроса.
Настоящая сеть и модель для тестов не нужны. CTest добавляет каталог Qt в PATH
для infra-тестов. Android-пресеты пока не подготовлены.

Часть infra-тестов автоматически запускает настоящий `msa_server` отдельным
процессом с временными настройками и базой. Независимый тестовый TCP/JSON-клиент
проверяет потерянное подтверждение записи, завершение LLM после обрыва,
переподключение/перезапуск и явный повтор без второго User. Локальная HTTP-модель
позволяет управлять моментом ответа; личные настройки не используются.
Подробнее — [ProtocolTestClient](docs/modules/ProtocolTestClient.md).

## Запуск сервера

1. Создайте личный файл из примера:

   ```powershell
   Copy-Item server.settings.json.example server.local.json
   ```

2. Замените все заглушки в server.local.json: адрес слушателя, токен, IANA-зону,
   endpoint сервисов, User-Agent с контактом, бюджет контекста и лимит генерации.
   Два числовых лимита задайте JSON-числами без кавычек. model можно оставить
   пустой строкой для выбора llama-server; api_key — пустой без Bearer.
   В SearXNG должен быть включён JSON API. database_path задаётся относительно
   каталога настроек либо абсолютным путём; его родительская папка должна существовать.
   Подробности — [сервер приложения](docs/modules/ServerRuntime.md).

3. В PowerShell из корня запустите сервер без окна:

   ```powershell
   $env:PATH = "C:\Qt\6.10.2\msvc2022_64\bin;$env:PATH"
   & .\out\build\windows-debug-local\Debug\msa_server.exe --config .\server.local.json
   ```

   Ожидается сообщение с TCP-портом, процесс продолжает работать. Ctrl+C завершает
   процесс. Если Qt установлен иначе, замените путь только в своей команде.
   Личный файл и файлы *.sqlite с журналами исключены через .gitignore.

База создаётся новой, без импорта старого проекта; текущая схема — версия 13.
При повторном запуске данные и ID основного чата сохраняются. Доступ к серверу
предполагается через Tailscale; собственного TLS нет. Новый клиент выполняет auth,
затем get_all и нужные операции по [протоколу](docs/protocol.md).
После потери ответа изменяющая операция не повторяется автоматически.
Пока выполняется внешний запрос, чтение и проверки сроков работают, новые
изменяющие операции получают busy. Уведомления не имеют очереди воспроизведения.
