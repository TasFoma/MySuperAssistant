# MySuperAssistant — правила проекта

## О проекте

Личный ассистент для ПК и смартфона: чат, музыка, напоминания, календарь, ментор/психолог,
геймификация в стиле Solo Leveling (уровни, квесты, статы).
Стек: C++20, CMake, Qt6 (Qt Quick/QML), Windows/MSVC и Android.
Qt установлен в `C:/Qt/6.10.2/` (`msvc2022_64` для ПК, Android-кит для телефона).

Три приложения из одного репозитория:
- `server` — «мозг» без окна: логика, данные, LLM. Клиенты подключаются к нему по сети.
- `desktop` — клиент для ПК.
- `mobile` — клиент для Android.

## Как работать (для агента)

- Работать только в этой папке. Старый проект `C:\Users\nasty\source\repos\MyAssistant`
  читать, только если пользователь явно назвал конкретный файл.
- Не делать рекурсивных листингов больших папок. Смотреть только то, что нужно для задачи.
- Одна задача — один результат. Перед изменениями показать короткий план.
- Не запускать сборку и долгие команды без просьбы: пользователь собирает сам и присылает ошибки.
- Не удалять файлы и не выполнять git-команды (commit, push, reset, checkout) без подтверждения.
- Не добавлять зависимости и не принимать архитектурных решений самостоятельно:
  смотреть `docs/decisions.md`, а если там нет решения, спросить.
- Если правило неясно или мешает задаче — спросить, а не угадывать.
- Отвечать по-русски, коротко, объяснять причину решений.

## Экономия: когда не делать самому, а дать инструкцию

Каждый шаг агента платный: в каждый запрос заново уходит вся история задачи, а вывод команд
ложится в контекст. Поэтому действия, которые пользователь сделает за пару кликов, агент
не выполняет сам, а пишет короткую инструкцию и ждёт ответа.

Пользователь делает сам, агент пишет шаги:
- создать, переименовать, переместить, удалить папки и пустые файлы;
- конфигурация CMake, сборка, запуск тестов и приложения — пользователь присылает только ошибки
  или итог;
- любые git-команды;
- установка программ, SDK, пакетов, настройка VS Code и Qt;
- поиск по старому проекту и просмотр больших папок — агент просит прислать нужный файл
  или список файлов.

Агент делает сам:
- создание и изменение файлов с кодом, CMake и документацией;
- правки, которые затрагивают несколько файлов.

Формат инструкции: нумерованные шаги, точные команды PowerShell в блоке кода,
что должно получиться в результате.
Если непонятно, что дешевле, — спросить одной строкой: «Сделать мне или написать шаги?»

## Архитектура

Каждый слой — отдельная библиотека CMake:

- `core` — логика предметной области (квесты, статы, напоминания, календарь, ментор)
  и общие типы данных. Только stdlib: никакого Qt, файлов, сети. Объявляет интерфейсы
  для внешнего мира (хранилище, часы, LLM, уведомления и т.п.).
- `infra` — реализации интерфейсов `core`: БД, JSON, сеть (сервер и клиент), LLM, аудио.
  Код под конкретную платформу — только в `infra/platform/<платформа>/`.
- `ui/common` — общие QML-компоненты и C++-модели для обоих клиентов.
- `ui/desktop`, `ui/mobile` — экраны под ПК и под телефон. Тонкие: логику не держат.
- `apps/<имя>/` — `main.cpp` каждого приложения: создаёт конкретные объекты и связывает слои.
- `tests` — тесты, в первую очередь `core`.

Зависимости только внутрь:
- `apps/server → infra, core`
- `apps/desktop → ui/desktop, ui/common, infra, core`
- `apps/mobile → ui/mobile, ui/common, infra, core`
- `ui/* → core`; `infra → core`; `ui` и `infra` друг о друге не знают.

- Зависимости передаются через конструктор. Никаких синглтонов и глобальных изменяемых переменных.
- Интерфейс заводится, когда есть две реализации (настоящая и тестовая, ПК и Android),
  а не «на будущее».
- Платформенный код (JNI, Android API) — только в `infra/platform/android/` за интерфейсом
  из `core`. Никаких `#ifdef Q_OS_ANDROID`, разбросанных по остальному коду.
- Пространства имён: `msa::core`, `msa::infra`, `msa::ui`.

## Структура

```
CMakeLists.txt  CMakePresets.json  .clang-format  .clang-tidy
cmake/   docs/   tests/
src/core/   src/infra/   src/ui/common/   src/ui/desktop/   src/ui/mobile/
src/apps/server/   src/apps/desktop/   src/apps/mobile/
src/<слой>/include/msa/<слой>/   — публичные заголовки
src/<слой>/src/                  — реализации
```

## CMake

- Только target-based: `target_link_libraries`, `target_include_directories`,
  `target_compile_features(... cxx_std_20)`.
- Запрещено: глобальные `include_directories`, `add_definitions`, `set(CMAKE_CXX_FLAGS ...)`.
- `core` линкуется только со stdlib.
- QML — через `qt_add_qml_module`, приложения — через `qt_add_executable`.
- Предупреждения в одном месте (`cmake/Warnings.cmake`): `/W4 /permissive-` для MSVC,
  `-Wall -Wextra -Wpedantic` для Clang (Android).
- Платформенные цели и исходники — под `if(ANDROID)` / `if(WIN32)` в CMake, а не в коде.
- Общие пресеты — в `CMakePresets.json` (windows-debug, windows-release, android-debug,
  android-release). Личные пути (Qt, Android SDK/NDK, JDK) — только в `CMakeUserPresets.json`,
  он не коммитится.

## Стиль C++

- Имена: camelCase — функции и переменные, `m_camelCase` — поля, PascalCase — типы,
  `kName` — константы. Не короче 3 символов; шаблонные параметры осмысленные (`ItemType`, не `T`).
- `std::ranges` где возможно. В лямбдах только явные захваты, никогда `[&]` и `[=]`.
- `const auto`, `auto*`, `auto&` — с явными квалификаторами; `typename`, а не `class`, в шаблонах.
- `[[nodiscard]]` на геттерах, чистых функциях и фабриках; `[[maybe_unused]]` для неиспользуемых
  параметров; `override` обязателен; `noexcept` только если тело очевидно не бросает.
- Фигурные скобки всегда, кроме одиночных `return`/`continue`/`break`/`throw`.
  Early return в начале функции. Пустая строка перед `return`, если перед ним несколько строк.
- Поля инициализируются через `{}`: `m_level{1}`.
- Владение: `std::unique_ptr` по умолчанию, `std::shared_ptr` только при совместном владении,
  сырые указатели не владеют. Без голых `new`/`delete`, кроме Qt-объектов с родителем.
- Без forward declarations — полные `#include`.
- Порядок include: свой заголовок (для .cpp) → проект → сторонние (Qt) → stdlib;
  группы разделены пустой строкой, внутри группы — по алфавиту.
- Реализации нешаблонных функций — только в .cpp. Локальные хелперы — в анонимном `namespace {}`.
- Порядок в классе: public → protected → private. В Qt-классах `signals:` перед `private slots:`,
  слоты начинаются с `on`, поля — отдельным `private:` блоком в конце.
- В `core` только std-контейнеры. Qt-типы — только в `ui`/`infra` и только там, где их требует
  Qt API. `QSignalBlocker` вместо `blockSignals()`.
- Магические числа — в именованные `constexpr` константы.
- Файл заканчивается пустой строкой.

## QML

- QML только показывает данные и передаёт действия пользователя в C++. Расчёты и правила — в C++.
- Повторяющиеся элементы (кнопки, карточки квестов, полоски статов) — компоненты в `ui/common`.
- Цвета, шрифты, отступы — в одном файле темы в `ui/common`, без хардкода в экранах.

## Комментарии

- На русском. Doxygen (`///`, `@brief`, `@param`, `@return`) — у публичных объявлений
  в заголовках; в .cpp не дублировать, там обычные `//` про логику и причину.
- Без банальностей, без истории кода («перенесено из...»), без закомментированного кода.

## Git

- Conventional Commits: `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `build:`, `chore:`.
- Агент только предлагает сообщение коммита; коммитит пользователь. Никогда `git add .`.
