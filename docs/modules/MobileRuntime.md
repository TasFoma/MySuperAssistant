# Запуск мобильного клиента

MobileRuntime в `src/apps/mobile/` соединяет MobileState/ClientModels,
строгие JSON-параметры и TCP-сессию. Общий ClientController из apps/common
передаёт типизированные действия и результаты, сохраняя правила desktop
(решение 61). UI не зависит от infra; мобильная связка не линкует desktop,
Vosk, музыкальный плеер или Windows-озвучку.

## Точки входа

- `include/msa/mobile/MobileRuntime.h`, `src/MobileRuntime.cpp`: start/stop,
  стабильные models/state, чтение и сохранение параметров, замена сессии.
- `src/main.cpp`: имена организации MySuperAssistant и приложения msa_mobile,
  CLI `--config <path>`, runtime и QQmlApplicationEngine. Статические плагины
  Msa.Ui.Common/Msa.Ui.Mobile импортируются до загрузки окна.
- `src/ui/mobile/UI/MobileWindow.qml`: окно с MobileShell и обязательными
  свойствами client/mobile. Размеры и цвета берутся из общей Theme.
- `MobileRuntimeOptions`: путь JSON и сроки подключения/ответа/повторов.
  По умолчанию 10 с, 180 с, задержки от 1 до 15 с; пять попыток задаёт TcpClient.
- CMake-цель `msa_mobile_support` — проверяемая часть apps/mobile;
  `msa_mobile` собирается также на Windows для offscreen-проверок.
  Android-упаковка сохраняет QT_QML_IMPORT_PATH обоих собственных QML-модулей.

## Параметры и подключение

Конструктор не читает файл и не включает сеть. После загрузки окна start
один раз читает client.settings.json через JsonClientPreferences. По умолчанию
это AppConfigLocation приложения msa_mobile, независимо от desktop. Отсутствие
или повреждение файла открывает настройки без сетевых попыток; повреждённый
файл автоматически не переписывается. CLI позволяет временный путь для тестов.

Схема версии 1 общая с ПК: host, port, token, auto_connect. Сохранение создаёт
каталог настроек и атомарно заменяет файл, только после успеха применяет
параметры к модели. Ошибка оставляет прежний сохранённый набор; токен не включается
в диагностику. «Сохранить» не меняет сеть. auto_connect учитывается при start;
«Подключиться» и ConnectionBanner используют последние сохранённые параметры.

Повтор к прежнему host/port/token сохраняет данные и выбранную беседу. Смена
любого из этих полей сначала завершает ожидавшие записи как unknown, закрывает
старую сессию и очищает серверные ID, списки и кэш. Черновик остаётся. Старые
записи автоматически не повторяются; отложенные ответы прежней сессии не
попадают в новую. Изменение только auto_connect не меняет принадлежность данных.

После обычного обрыва видны последние данные в памяти с признаком stale,
серверные действия недоступны. Пять неудачных попыток останавливают цикл до
ручного действия. stop и aboutToQuit отменяют повторы и завершают запросы
до удаления контроллера; start после stop ничего не запускает.

## Проверки и ограничения

`tests/infra/src/MobileRuntimeTest.cpp` в msa_ui_tests использует offscreen,
локальные сокеты и временные файлы. Проверяет первый запуск/повреждение,
ошибку сохранения, auto_connect=false, сохранение без подключения, явное
применение и повтор, смену сервера с неподтверждённой записью без её повтора,
исчерпание попыток и остановку. Окно создаёт задачу через настоящий msa_server
с временной SQLite-базой и сохраняет последние данные после остановки сервера.
Отдельный msa_mobile проверяет main, CLI, оба QML-плагина и подключение.

Рендеры: mobile-startup-preview.png, mobile-startup-invalid-preview.png и
mobile-runtime-preview.png в out/build/windows-debug-local.
Настоящие Tailscale/LLM, установка APK, системная клавиатура и кнопка Назад
на A55 требуют проверки на устройстве. Android Debug APK с этой связкой
собран 2026-11-15: AAPT2 подтвердил минимум API 28, target API 36, arm64-v8a
и INTERNET; проверено наличие libmsa_mobile_arm64-v8a.so и платформенного
плагина Qt. Vosk, voice_worker и Qt TextToSpeech в APK отсутствуют.
Инструкция установки и первого подключения находится в README.
Уведомления, фоновая служба, геолокация, речь Android и постоянный
кэш серверных данных не реализованы этим шагом. Сворачивание окна само по себе
не создаёт фонового сервиса; доставка после остановки приложения не гарантируется.

Проверка 2026-11-15: конфигурация и сборка windows-debug-local успешны,
все 530 тестов зелёные, включая семь MobileRuntimeTest и прежние проверки desktop.
Три рендера нового окна просмотрены.
