# SqliteChatRepository

SQLite-реализация `core::ChatRepository` в `infra`. Сохраняет несколько чатов,
полные сообщения User/Assistant и выбранный чат между открытиями файла.
Правила поведения — решения 33 и 40. Публичный API описан в
`src/infra/include/msa/infra/SqliteChatRepository.h`, реализация —
`src/infra/src/SqliteChatRepository.cpp`.

## Открытие и схема

Вызывающая сторона создаёт `QCoreApplication`, затем
`SqliteDatabase{path, sqliteMigrations()}`, затем репозиторий со ссылкой на базу.
Владелец базы живёт дольше репозитория; все операции выполняются в его потоке.
Список `sqliteMigrations()` из `SqliteSchema.h/.cpp` передаётся при каждом открытии.
Базовый конструктор без списка по-прежнему знает только версию 1.
ServerRuntime создаёт базу и репозиторий в одном потоке владельца.

Миграция 2 атомарно добавляет:

- `chats`: положительный ID, название и местное время создания;
- `chat_messages`: ID, внешний ключ чата, роль, полный текст и время;
- индекс `chat_messages_by_chat` по чату и ID;
- `chat_selection`: единственную строку с ключом 1 и внешним ключом выбранного чата.

ID назначает SQLite через INTEGER PRIMARY KEY AUTOINCREMENT; ID чатов и сообщений
независимы. Время — знаковое целое количество секунд местной шкалы chrono,
без преобразования часового пояса. Роли хранятся строками User/Assistant с CHECK.
Тексты передаются параметрами подготовленных запросов в UTF-8, включая пробелы,
переносы, emoji и встроенный нулевой символ. Ограничений длины и автоочистки нет.

## Операции и ошибки

Миграция 13 добавляет server_state с единственным main_chat_identifier и внешним
ключом на chats. ensureMainChat атомарно читает его либо создаёт чат «Основной»
и сохраняет ID. Название не используется как ключ; chat_selection не меняется.
ServerRuntime вызывает это при запуске и использует сохранённый ID для проактивных
сообщений. Повторное открытие проверяется в tests/infra/src/ServerRuntimeTest.cpp.

`addChat` и `addMessage` назначают ID, не меняя исходный объект. Ненулевой входной
ID и неизвестная роль приводят к `std::invalid_argument`. Проверки пользовательского
текста остаются в ChatService. Списки и поиск возвращают независимые копии;
порядок задаёт ChatService, контракт репозитория его не гарантирует.

Несуществующий чат даёт nullopt при поиске/добавлении сообщения, пустой список
сообщений и false при сохранении выбора. До первого выбора возвращается nullopt.
Проверка существования и запись выполняются одним INSERT SELECT, выбор заменяется
через UPSERT. Поэтому неверный ID не сбрасывает предыдущий выбор.
Внешние ключи не допускают сообщений и выбора без чата. SQL-ошибки и ошибки чтения
передаются через `std::runtime_error`, без Qt-исключений и маскировки пустым результатом.

Все записи используют соединение переданного SqliteDatabase и участвуют в его
внешней транзакции; ensureMainChat использует TransactionRunner базы. ConversationService
сохраняет Assistant вместе с дневником, профилем и снятием ожидания через общий
TransactionRunner. User сохраняется до LLM, вне этой транзакции.
Создание чата и сохранение выбора в ChatService пока остаются двумя операциями.
Редактирования и удаления чатов/сообщений нет; импорта старой базы нет.

## Тесты

`tests/infra/src/SqliteChatRepositoryTest.cpp`: 10 тестов на временных файлах.
Проверяются миграция с версии 1 и повторное открытие, постоянные ID, выбор,
отсутствующие чаты, полный длинный Unicode-текст с NUL и SQL-подобными строками,
роли, отрицательное время и перевод часов, раздельные истории, копии и повторы,
ограничения схемы, откат внешней транзакции, ошибки SQL и восстановление ChatService.
Команды запуска — в [README](../../README.md).
