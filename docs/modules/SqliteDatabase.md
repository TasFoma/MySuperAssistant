# SqliteDatabase

Основа SQLite в `infra` по решению 40: именованное соединение Qt Sql,
версия схемы, последовательные миграции и транзакции. Публичные заголовки —
`src/infra/include/msa/infra/SqliteDatabase.h`, `SqliteMigration.h`;
реализация — `src/infra/src/SqliteDatabase.cpp`.

Система начинает работу с новой пустой базой. Импорта старой базы нет.
Базовый конструктор без дополнительных миграций не создаёт предметные таблицы.
`sqliteMigrations()` из SqliteSchema добавляет версию 2 для
[SqliteChatRepository](SqliteChatRepository.md): чаты, сообщения и выбор.
Версия 3 добавляет полный профиль и теги для
[SqliteUserProfileRepository](SqliteUserProfileRepository.md), включая источники и версии.
Версия 4 добавляет дату приветствия для
[SqliteGreetingRepository](SqliteGreetingRepository.md).
Версия 5 добавляет дату вечернего опроса и ожидание ответа для
[SqliteEveningCheckInRepository](SqliteEveningCheckInRepository.md).
Версия 6 добавляет отметки предупреждений для
[SqliteEventWarningRepository](SqliteEventWarningRepository.md).
Версия 7 добавляет дневник для [SqliteMoodRepository](SqliteMoodRepository.md)
и внешний ключ source_mood в профиле, сохраняя его факты, теги и версии.
Версия 8 добавляет задачи для [SqliteTaskRepository](SqliteTaskRepository.md).
Версия 9 добавляет серии событий для [SqliteEventRepository](SqliteEventRepository.md).
Версия 10 добавляет все виды напоминаний для

## Точки входа и время жизни

- Конструктор открывает файл, включает и проверяет внешние ключи, определяет
  принадлежность и версию, затем применяет недостающие миграции одним пакетом.
- `schemaVersion` читает целый PRAGMA user_version.
- `connection` даёт невладеющий доступ для QSqlQuery репозиториев.
- `execute` выполняет один SQL-оператор и преобразует ошибку в std::runtime_error.
- `transaction` исполняет callback один раз с фиксацией или откатом по исключению.

Нужен живой QCoreApplication. Каждое соединение имеет уникальное имя;
соединение по умолчанию и собственный глобальный объект БД не используются.
Владелец не копируется и не перемещается. Он живёт дольше репозиториев, запросов
и любых копий QSqlDatabase, а уничтожается до QCoreApplication, в том же потоке.
После освобождения внутреннего handle соединение удаляется из реестра Qt.
Неудачный конструктор тоже освобождает регистрацию.

Ограничения потока и живых ссылок следуют из
[контракта QSqlDatabase Qt 6.10](https://doc.qt.io/qt-6.10/qsqldatabase.html).
Модуль проверяет поток при обращении, но не переносит соединение и не запускает
потоки самостоятельно. Внешние запросы нужно завершать до конца callback.

## Базовая версия и миграции

Версия 1 помечает пустой файл application_id=0x4D534131 (MSA1) и user_version=1.
Предметных таблиц и строк в этой версии нет. Эти поля определены
[SQLite PRAGMA](https://www.sqlite.org/pragma.html).
Чужой application_id, неизвестные объекты в неверсионированном файле,
отрицательная или более новая, чем известная программе, версия отклоняются
без изменения существующей схемы и данных. Модуль не сбрасывает и не перезаписывает
чужую базу. Пустой путь запрещён; родительские каталоги автоматически не создаются.

Следующие версии передаются конструктору как упорядоченный список SqliteMigration:
2, 3 и далее без пропусков и повторов. Каждый элемент содержит отдельные доверенные
SQL-константы, по одному оператору на строку списка. Уже применённые версии
пропускаются. На успешном переходе обновляется user_version.

Базовая и все недостающие миграции выполняются в одной транзакции. При ошибке
поздней миграции откатываются более ранние изменения из этого запуска, включая
DDL, данные, application_id и номер версии. При повторном открытии вызывающая
сторона обязана передать полный известный ей список миграций. Базовый конструктор
без дополнительных миграций отклонит файл версии 2 и выше.

Миграции следующих таблиц добавляются вместе с репозиториями; тестовые
таблицы entries/parent/child не являются схемой приложения. Нет проверки хеша
или полного состава схемы уже помеченного файла; принадлежность и версия не
доказывают отсутствие ручного изменения таблиц.

## Транзакции

Все уровни реализованы через именованные SAVEPOINT. Нормальный возврат callback
выполняет RELEASE; исключение — ROLLBACK TO и RELEASE с пробросом исходной ошибки.
Внутренний успех остаётся частью внешней транзакции. Пойманная ошибка внутреннего
callback позволяет продолжить внешнюю операцию без его изменений. Семантика
соответствует [SQLite Savepoints](https://www.sqlite.org/lang_savepoint.html).

Ошибка окончательной фиксации, например отложенного внешнего ключа, тоже вызывает
откат. Если откат не удался, соединение закрывается; дальнейшие операции отказывают.
Ошибка отката передаётся вложенным исключением. Для восстановления нужен новый владелец.

Callback обязан сообщать отказ исключением: возвращаемый bool или variant
не анализируется. Репозитории не должны выполнять собственные BEGIN/COMMIT,
менять служебные PRAGMA или закрывать соединение. SQL миграций доверенный;
тексты и числа пользователя будущие репозитории передают подготовленными запросами.
Операции не повторяются автоматически, распределённых транзакций нет.

SqliteDatabase реализует [TransactionRunner](TransactionRunner.md) из core
существующим методом transaction. ConversationService получает того же владельца,
что и его репозитории. User сохраняется до LLM; дневник, профиль, Assistant и
снятие действительного ожидания записываются одной транзакцией после ответа.
Во время вызова модели транзакция не держится. Публикация опроса использует другую
транзакцию того же исполнителя: дата, сообщение и ожидание фиксируются вместе,
включая очистку старого ожидания. Для этой операции отдельная миграция не нужна.
Текущая версия схемы — 12: история расчётов маршрутов и постоянный кэш геокодинга.

## Сборка и тесты

Qt Sql ищется один раз в корневом CMake. msa_infra публично линкуется с Qt6::Sql,
поскольку публичный заголовок содержит Qt-типы. core остаётся без Qt.
apps/server получает Qt Sql транзитивно, но пока не создаёт базу.

`tests/infra/src/SqliteDatabaseTest.cpp`: 14 сценариев временных файлов, повторного
открытия и Unicode, версий и миграций, отказа чужой/новой схемы, отката DDL/данных,
вложенных транзакций, ошибки commit и отката, освобождения соединений и неверного ввода.
`TestMain.cpp` создаёт QCoreApplication без окна. Тестовые файлы создаются через
QTemporaryDir внутри рабочего каталога CTest и автоматически убираются после теста.

Цель msa_infra_tests использует gtest_add_tests для регистрации сценариев без
запуска Qt-программы во время сборки. На Windows CTest добавляет каталог Qt Core
в PATH для этой группы тестов через ENVIRONMENT_MODIFICATION; личный PATH не меняется.
QSQLITE берётся из установленного Qt. Команды — в [README](../../README.md).
