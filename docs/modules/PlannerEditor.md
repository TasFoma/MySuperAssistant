# Формы действий планировщика

PlannerEditor в `src/ui/desktop/Model/include/msa/ui/PlannerEditor.h` и
`Model/src/PlannerEditor.cpp` хранит одну открытую форму, её поля и состояние
подтверждения. DesktopState владеет им и предоставляет свойство planner.
UI получает типизированные данные core и не знает о JSON или TCP.

## Точки входа и формы

Методы newTask/editTask/deleteTask, newEvent/editEvent/deleteEvent,
newHabit/recordHabit/deleteHabit и newReminder/deleteReminder открывают формы.
fields содержит описания текстовых полей, многострочного описания и списков
вариантов. setField/setChoice сохраняют ввод; submit проверяет его и передаёт
действие ClientModels; cancel закрывает форму без записи.
fieldVisibility меняет видимость без пересоздания делегатов, сохраняя фокус
ComboBox при последовательном переключении стрелками.

- Задача: название, необязательная дата срока, приоритет. Изменение не передаёт
  done и createdAt, поэтому сохранённая завершённость и время создания остаются.
- Событие: название, исходная дата, необязательное время, описание и повтор.
  Форма берёт date исходной серии, а не occurrenceDate показанного вхождения.
  Перед изменением и удалением явно поясняется действие над всей серией.
- Привычка: название, положительная конечная цель, необязательная единица,
  день/неделя. Отметка добавляет положительное число за день сервера; количество
  не ограничивается целью. Числа можно вводить с точкой или запятой.
- Напоминание: по времени, повторяющееся или по месту. Вид переключает видимые
  поля и сохраняет уже введённый текст. Время вводится в местной шкале серверной
  зоны; первый срок повтора определяет сервер. Для места передаётся название
  без нулевых или угаданных координат.
- Удаление: отдельная форма подтверждения с названием записи. Для привычки
  поясняется удаление журнала, для события — всей серии. Отмена ничего не отправляет.

Проверки формы не подменяют предметные сервисы: допустимость срока и прочие
правила окончательно проверяет сервер. Даты/время разбираются строго в ISO и
ЧЧ:ММ; ID проходят каноническое преобразование в int64 без потери точности JS.

## Подтверждение и потеря связи

submit создаёт один ClientPlannerAction, блокирует повторную отправку/изменение
полей и ждёт результата. Строки списков не изменяются оптимистично. Контроллер
приложения сообщает ClientModels::finishPlannerAction только после строгой
проверки подтверждения или установленного отказа. Успех закрывает лишь форму
с совпадающим действием; новые строки приходят обычным обновлением данных.

При отказе форма и ввод остаются, ожидание снимается. Ошибка формы относится
к её запросу; прежняя глобальная unknown другой операции не подменяет её текст
или эффект и при этом сохраняется в общих моделях.
При unknown или изменении сессии повтор запрещён до закрытия и явного открытия формы после проверки
обновлённых данных. Позднее подтверждение не закрывает такой черновик.
Автоматического replay, записи без связи и очереди изменений нет.
Серверные кнопки отключены без Ready и принятого снимка; просмотр данных остаётся.

## Типизированная граница

`src/core/include/msa/core/ClientPlannerAction.h` содержит структуры сохранения
задачи/события, создания/отметки привычки, удаления и трёх напоминаний. Это новая
альтернатива внутри существующего ClientAction, не сетевой интерфейс или слой.
ClientProtocol передаёт её внутреннему ClientPlannerProtocol в infra.
Он кодирует существующие методы версии 1 и проверяет точные подтверждения:
ID создания/изменения, совпадение ID при update, deleted=true без лишних полей.
Неверное подтверждение записи получает unknown и отключение, как раньше.

PlannerDialog в UI отображает метаданные формы и вызывает методы C++.
RecordActions в ui/common — общие кнопки изменения/удаления; EventRecord
в ui/desktop повторно используется для сегодняшних и выбранных событий.
Все размеры и цвета — из Theme. Ни один компонент сам не повторяет запрос.

## Ограничения и проверки

Редактирование привычек и напоминаний не имитируется удалением/созданием:
таких update-методов в протоколе нет. Выбор кандидата адреса/разрешение геолокации
и назначение точки геонапоминания остаются отдельной функцией; форма сохраняет
напоминание по месту без координат и явно поясняет это.
Пользовательское окно/сессия в main и музыкальный плеер ещё не подключены.

`tests/infra/src/PlannerActionsTest.cpp` проверяет все виды запросов и подтверждений,
строковые большие ID, исходную дату серии, дроби, валидацию, отмену, подтверждение,
отказы, unknown и поздние ответы. ServerRuntimeTest проверяет цепочку формы →
контроллер → TCP → настоящий ServerRuntime/SQLite → обновлённые модели.
DesktopScreensTest проверяет настоящий клавиатурный ввод в форме, ComboBox,
отмену удаления, отсутствие QML-предупреждений и сохранение текста.
Рендеры: `out/build/windows-debug-local/planner-task-preview.png` и
`planner-reminder-preview.png`; видимое пользовательское окно не запускается.
