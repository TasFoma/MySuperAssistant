# LlamaClient

HTTP-реализация `core::LlmClient` в `infra`: один POST на llama-server,
полный структурированный ответ без потоковой выдачи, повторов и записи данных.
Заголовок — `src/infra/include/msa/infra/LlamaClient.h`, реализация —
`src/infra/src/LlamaClient.cpp`.

## Точки входа

- `LlamaClientSettings`: полный URL `/v1/chat/completions`, необязательные модель
  и Bearer-токен, обязательные положительные timeout и maxResponseTokens.
- `LlamaClient`: получает настройки и внешний `QNetworkAccessManager` через
  конструктор. Неверные настройки вызывают `std::invalid_argument` до сети.
- `LlmClient::complete`: проверяет запрос в core, вызывает адаптер и проверяет
  результат; подставляет полный исходный User в заметку дневника.

Менеджер должен пережить клиент и запросы. Нужен `QCoreApplication`.
Менеджер и вызовы должны находиться в одном рабочем потоке с диспетчером событий.
Синхронный контракт реализован локальным `QEventLoop`; в UI вызывать нельзя.
Цикл обрабатывает события рабочего потока: приложения должны исключить повторный
вход в связанные сервисы. Повторный вход в сам адаптер возвращает Unavailable.
Создание и связывание в `apps/server` пока отсутствуют.

## Запрос

Сообщения System/User/Assistant и полные тексты передаются в исходном порядке,
без добавления промпта и повторного добавления текущего вопроса. Промпт и состояние
опроса уже подготовлены `MentorPrompt` и `ConversationService`.
`profileFactIdentifiers` проверяет core, отдельного поля API для него нет.

Тело содержит stream=false, max_tokens из настроек и response_format=json_object.
JSON-режим описан в [документации llama-server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md).
Параметры обычного чата сохранены из старого клиента: temperature=0.6, top_p=0.9,
top_k=40, repeat_penalty=1.1. Пустая model не отправляется.
Bearer-заголовок добавляется только при непустом токене; перенаправления не выполняются.
Пароль в URL, query, fragment и переносы строк в токене отклоняются.

## Ответ и ошибки

Успешен только HTTP 200 без сетевой ошибки. Конверт должен содержать ровно один
choices, finish_reason=stop, роль assistant и строковый message.content.
Вызовы инструментов, незавершённая генерация и конверт с error отклоняются.
Неизвестные служебные поля конверта допускаются: например usage и timings.

Содержимое разбирается как один JSON-объект по [контракту core](LlmClient.md).
Проверяются обязательные и дополнительные поля, типы, оценки и причины записи.
ID исправления должен быть положительным целым int64, затем core проверяет
его присутствие в контексте и отсутствие повторной замены. Полные тексты
не обрезаются; пустые после Unicode-trim значения отклоняет core.
Qt JSON при повторном имени ключа оставляет последнее значение; отдельной
проверки повторных ключей адаптер не выполняет.

Ошибки сети, HTTP и общий тайм-аут — Unavailable. Неверный конверт, JSON,
обрыв по лимиту генерации и неверные значения — InvalidResponse. Частичного
ответа нет. При тайм-ауте запрос прерывается; срок включает получение тела,
даже если сервер продолжает присылать данные. Причины не содержат адрес,
токен, errorString или тело технического ответа. Логирование переписки отсутствует.

Обрезка по ChatML-маркерам и подстановка «(нет ответа)» из старого клиента не
переносятся: контракт требует полный проверенный JSON. Поиск остаётся отдельным
путём WebSearchProvider и передаётся сервером по явному search_query. Старые промпт и сборка истории заменены уже согласованными
MentorPrompt и LlmContextBuilder.

## Ограничения и тесты

maxResponseTokens ограничивает генерацию, но не проверяет вместимость запроса.
Точный бюджет токенов, резерв ответа и обработку превышения окна ещё предстоит
согласовать при интеграции модели. JSON-режим не доказывает правильность анализа,
фактов и предложений дневника. Проверки настоящей модели пока не выполнены.
Отмена пользователем и ограничение размера HTTP-тела пока не реализованы.

`tests/infra/src/LlamaClientTest.cpp`: подменённый QNetworkAccessManager возвращает
QNetworkReply без сокетов. Проверяются тело/порядок запроса, настройки и авторизация,
полный ответ, заметка и факты, неверные структуры/типы/ID, ожидание опроса,
неполные ответы, HTTP и сетевые ошибки, тайм-аут и явный повтор.
Команды проверки — в [README](../../README.md).
