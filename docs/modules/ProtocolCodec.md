# ProtocolCodec и ProtocolPayload

Модуль `infra` реализует формат [протокола версии 1](../protocol.md) без сокетов,
записи в БД и выполнения команд. Зависит от существующих Qt Core и типов `core`.

## Точки входа

- `ProtocolMessage.h` — вариант шести конвертов: auth, request, успешный ответ,
  отказ, событие и protocol_error; версия, предел кадра и срок авторизации.
- `ProtocolCodec::decode` — разбирает один завершённый кадр без LF. Проверяет
  UTF-8 без BOM, JSON-объект, точный состав полей, типы, параметры всех 33 методов,
  данные пяти событий и каталог ошибок. Дубликаты ключей разбирает Qt: последний побеждает.
- `ProtocolCodec::encode` — проверяет конверт теми же правилами, выдаёт компактный
  UTF-8 JSON и LF. Превышение размера даёт response_too_large без обрезки текста.
- `ProtocolFrameDecoder::append` — выделяет строки из блоков байтов, сохраняя
  незавершённый хвост. `reset` отбрасывает хвост и ошибку при закрытии соединения.
- `ProtocolPayload` — переводит сохранённые предметные объекты core в JSON:
  задачи, календарь/вхождения, привычки/прогресс, три вида напоминаний, беседы,
  сообщения, дневник, факты/источники, поиск, маршруты/статистику и погоду.

## Проверки и обработка ошибок

ID проверяются строками до int64 max, без преобразования через double. Даты,
время, местные секунды, nullable поля, перечисления и координаты проверяются
до исполнения. Нулевые координаты допустимы. Проверки непустого текста не
изменяют исходные пробелы и переводы строк. Параметры остаются QJsonObject
после проверки схемы; доменное выполнение принадлежит будущим обработчикам.

Неверный формат кадра возвращает `ProtocolDecodeError` с closeConnection=true.
Надёжный request_id сохраняется при отказе параметров/метода, чтобы сервер
смог ответить коррелированно. Ошибка не содержит исходный кадр или токен.
Кодек не создаёт человеческое описание ошибки: это ответственность адаптера.

Накопитель ограничивает даже незавершённую строку 1 048 576 байтами. LF не
включается в предел. После пустой строки/превышения размера он остаётся в
состоянии отказа до reset. Возвращённые перед отказом кадры сохраняют порядок.
JSON/UTF-8 проверяет отдельно кодек; потребитель разбирает кадры последовательно
и прекращает обработку при первом фатальном отказе. EOF никогда не исполняет хвост.
Экземпляр накопителя принадлежит одному соединению.

ProtocolPayload отвергает некорректные значения через std::invalid_argument:
несохранённые ID, даты, перечисления, UTF-8, бесконечные числа и нарушенные
ограничения координат/погоды/напоминаний. Местное время не переводится в UTC.
Для отсутствующего съезда или прогноза не подставляются выдуманные значения.

## Ограничения

Успешный result — JSON-объект: его состав определяется методом исходного запроса,
которого нет в ответном конверте. Обработчики ServerRuntime собирают результаты через
ProtocolPayload; клиентские адаптеры должны проверять ожидаемую схему результата.
Кодек не проверяет существование записей, принадлежность предложения сессии,
уникальность request_id, правильность токена, поддерживаемую версию или тайм-аут.
Авторизацию, уникальность request_id и тайм-аут реализует [TcpServer](TcpServer.md);
предметные проверки остаются приложению. Неизвестная числовая
версия auth разбирается, чтобы сервер мог ответить unsupported_version.

## Тесты

`tests/infra/ProtocolCodecTest.cpp`: 19 тестов. Все методы имеют допустимые примеры;
для каждого проверены лишние, пропущенные и неверно типизированные параметры.
Проверены конверты, сохранение текста, int64, даты, enum, null, границы координат,
разрывы UTF-8 в каждой позиции, несколько кадров, EOF/reset, повреждённый ввод,
лимит кадра и предметная сериализация. Сокеты и настоящий сервер не используются.
