# SqliteHabitRepository

SQLite-реализация `core::HabitRepository` по решениям 14, 15, 21 и 40.
Хранит привычки и полный журнал; прогресс вычисляет HabitService.
Заголовок — `src/infra/include/msa/infra/SqliteHabitRepository.h`, реализация —
`src/infra/src/SqliteHabitRepository.cpp`.

## Схема и точки входа

Конструктор получает невладеющую ссылку на SqliteDatabase с полным списком
`sqliteMigrations()`. База живёт дольше репозитория, работа — в потоке владельца
при живом QCoreApplication. Приложения пока не создают репозиторий.

Миграция 11 добавляет `habits` и `habit_logs`. Обе таблицы используют INTEGER
PRIMARY KEY AUTOINCREMENT с независимыми последовательностями ID. Привычка
содержит полные name/unit, вещественную цель target и период Day/Week (0/1).
Отметка хранит внешний ключ привычки, календарные год/месяц/день и вещественное
value. Индекс по привычке и ID ускоряет чтение журнала. Даты не содержат часового
пояса. Прежние таблицы миграция не меняет.

`add` назначает ID новой привычке с нулевым ID. `find` возвращает копию либо
nullopt, `all` — независимые копии без гарантии порядка. `update` заменяет все
поля привычки без изменения журнала, при отсутствии — false без вставки.
`remove` удаляет привычку и её журнал одним DELETE с ON DELETE CASCADE,
при отсутствии — false. ID удалённых зафиксированных записей не используются повторно.

`addLog` назначает ID новой отметке с нулевым ID. Проверка существования привычки
и вставка — один INSERT SELECT; при отсутствии — nullopt без записи. Повторные
отметки сохраняются отдельно. `logs` возвращает копии всех отметок указанной
привычки без гарантии порядка, для отсутствующей — пустой список.

Полные тексты передаются параметрами запросов, без обрезки и ограничения длины,
включая пробелы, переносы, Unicode и NUL. Цель и значение должны быть положительными
конечными double, период — Day/Week, дата отметки — корректной. Неверные поля
и ненулевой ID новой записи вызывают std::invalid_argument. SQL-ошибки и неверные
данные при чтении — std::runtime_error без маскировки отсутствием записей.

## Транзакции и ограничения

Каждая запись — один SQL-оператор, участвующий во внешней транзакции SqliteDatabase.
Каскадное удаление атомарно: ошибка удаления отметки сохраняет привычку и журнал.
Откат внешней транзакции восстанавливает оба набора данных.

Автоматической очистки и импорта старой базы нет. Старые и будущие отметки
хранятся полностью; выбор периода и суммирование выполняет HabitService.
Изменение периода не удаляет журнал. Сервис читает все привычки и их журналы
без общей транзакции; конкурентные изменения не согласуются. Исправления
отдельных отметок, постраничной загрузки, UI и доставки клиентам нет.

## Тесты

`tests/infra/src/SqliteHabitRepositoryTest.cpp`: семь файловых тестов.
Проверяются обновление с версии 10 без потери напоминаний, повторное открытие,
все поля, постоянные ID, длинные тексты с NUL, дробные/повторные отметки, копии,
смена периода без потери журнала, отсутствующие записи, неверные числа/даты/ID,
внешний ключ, каскадное удаление, сбой каскада, SQL-ошибки и общий откат.
HabitService с FakeClock восстанавливает дневной/недельный прогресс, допускает
превышение цели и сохраняет старые/будущие записи для дальнейшего просмотра.
Команды — в [README](../../README.md).
