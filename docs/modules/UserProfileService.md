# UserProfileService

Добавление фактов памяти пользователя без Qt, файлов и сети. Единственная
зависимость — `UserProfileRepository`, переданный через конструктор.

## Точки входа

- `rememberFact` — обрезает пробельные символы Unicode по краям, отклоняет пустой
  результат либо добавляет факт в конец загруженного профиля и сохраняет профиль целиком.
- `profile` — возвращает независимую копию всех фактов в порядке добавления.
- `validateExtractedFacts` — проверяет пакет предложений LLM на копии без записи.
- `rememberExtractedFacts` — сохраняет пакет с источником одним save; возвращает
  новые факты/версии либо UserProfileRejection.

`UserProfileFact` в `UserProfile.h` содержит полный текст, необязательные ручные
теги и alwaysInclude. `rememberFact` принимает теги и признак приоритета;
прежний вызов с одним текстом сохраняет факт без тегов с alwaysInclude=false.
Теги обрезаются по краям по правилам Unicode; пустой тег отклоняет всю операцию
до чтения или записи профиля. Регистр, внутренние пробелы и повторы тегов сохраняются.
Теги могут содержать несколько слов. Для поиска их разбирает
[UserProfileFactSelector](UserProfileFactSelector.md); alwaysInclude даёт приоритет
кандидата, но не отменяет общий бюджет контекста.

## Правила

Ручное rememberFact сохраняет повторы и назначает постоянный положительный ID.
Внутренние пробелы и переносы строк
не меняются; многострочный текст занимает один элемент списка. Маркеры оформления
не добавляются. Ограничение последних 30 фактов отменено решением 27.
Функция обрезки находится во внутреннем `Utf8Text`, ожидающем текст UTF-8.

Неверный текст/тег ручного ввода возвращает `UserProfileRejection` без обращения к
репозиторию. Успех rememberFact — `std::monostate`. Технические исключения пробрасываются.

## Автоматические факты и версии

Правила — решение 39. ProfileFactProposal из одноимённого заголовка содержит
текст и необязательный ID заменяемой актуальной версии. Факты извлекает модель
из текущего сообщения в том же запросе чата. Автоматических тегов нет.
ID новой записи — максимум существующих ID плюс один. Сохранённые ID должны
быть положительными и уникальными; исчерпание диапазона вызывает overflow_error,
неверные ID хранилища — runtime_error. profile ничего не нормализует;
старые SQL-данные ещё не переносились.

ProfileFactSource хранит ID чата, исходного User и необязательный ID дневника.
Сервис проверяет положительность ссылок; существование источников обеспечивает
ConversationService. Полный исходник остаётся в истории, факт может быть кратким.
У ручного факта источник необязателен. ID и ссылки модель не назначает.

Тексты обрезаются по краям. Новый факт без замены пропускается при точном
совпадении с любым сохранённым текстом, в том числе внутри пакета. Регистр
и внутренние пробелы значимы. Похожие формулировки не объединяются. Повтор
не активирует старую версию. Пустой пакет и одни повторы не вызывают save.

Исправление создаёт запись с replacesFactIdentifier, старая получает
supersededByFactIdentifier. Её текст, источник и метаданные сохраняются.
Новая версия наследует теги и alwaysInclude. Старый текст может вернуться
как новая версия при явной замене текущей; без замены это повтор.
Замена текстом самой цели ничего не записывает. Неизвестная/неактуальная цель,
две замены одной цели или совпадение с другой актуальной записью отклоняют
весь пакет: неоднозначные версии не объединяются автоматически.

Пакет применяется к копии и сохраняется один раз после полной проверки.
Поздний отказ не оставляет ранних добавлений или отметок замены в хранилище.
validateExtractedFacts использует ту же проверку без save. Это не транзакция
с дневником и чатом; конкурентные операции между проверкой и записью не поддерживаются.
profile возвращает все версии; UserProfileFactSelector исключает заменённые из контекста.

## Ограничения и тесты

Сервис пока не связан с парсером и приложениями. Хранение на диске реализует
[SqliteUserProfileRepository](SqliteUserProfileRepository.md), схема версии 3.
Интерфейса редактирования тегов сохранённых фактов и удаления фактов нет. Исправления через предложение
LLM создают версии. Теги и приоритет задаются при ручном добавлении факта;
отбор выполняет отдельный UserProfileFactSelector, бюджет — LlmContextBuilder.
Весь профиль загружается и сохраняется целиком; нет защиты от потерянных
обновлений при конкурентных операциях. Уже сохранённые факты не нормализуются.

`tests/core/src/UserProfileServiceTest.cpp` проверяет сохранение более 30 фактов без
потерь и в исходном порядке, чтение через другой экземпляр сервиса, независимость
копий, повторы, односимвольный и многострочный текст, пробельные символы Unicode,
отказ без доступа к хранилищу и проброс ошибок чтения/сохранения.
Два дополнительных сценария проверяют теги и приоритет при сохранении и повторном
чтении, независимость копий метаданных, значения по умолчанию и отказ для пустого тега.

`tests/core/src/ProfileFactImportTest.cpp`: восемь сценариев ID и источников,
повторов и ручного добавления, цепочки версий, исключения старой памяти,
отказа всего пакета, неоднозначных исправлений, одного save, ошибок и исчерпания ID.
Качество извлечения фактов настоящей моделью ещё не проверено.
