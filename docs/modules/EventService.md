# EventService

Создаёт и изменяет календарные события без Qt, файлов и сети. Получает невладеющую
ссылку на `EventRepository` через конструктор; репозиторий живёт дольше сервиса.
Чтение календаря с повторами выполняет [CalendarService](CalendarService.md).

## Точки входа и правила

- `addEvent` сохраняет новое событие с назначением положительного ID.
- `updateEvent` заменяет название, дату, время, описание и повтор по ID.

Обе операции используют одну проверку: минимум одна кодовая точка в названии,
корректная обязательная дата, необязательное время в пределах 00:00–23:59 и одно
из значений повтора None, Daily, Weekly, Monthly. Описание может быть пустым.
Прошедшие даты разрешены. Текст сохраняется без обрезки пробелов.
Минимальная длина в парсере команд этим сервисом не меняется (решение 24).

Изменяется вся серия, включая исходную дату начала, с сохранением ID.
Отдельные вхождения не хранятся и не редактируются. Удаление доступно через репозиторий.

## Результаты и ограничения

Создание возвращает ID либо `EventRejection` с причиной. Изменение возвращает
`std::monostate` при успехе либо отказ, в том числе при отсутствии записи.
Неверный ввод отклоняется до обращения к хранилищу. Технические исключения
репозитория пробрасываются вызывающему коду без преобразования в отказ проверки.
Изменение заменяет все поля записи; согласования конкурентных изменений нет.

Сервис пока не подключён к парсеру, приложениям и уведомлениям. Часы не нужны:
текущий момент не влияет на допустимость события и не сохраняется в его типе.
Хранение на диске реализует [SqliteEventRepository](SqliteEventRepository.md),
схема версии 9; отдельные вхождения по-прежнему вычисляет CalendarService.

пустые необязательные поля, високосная дата, границы времени, все повторы,
неверный ввод без записи и изменения, отсутствие ID, изменение всей серии
и результат в календаре с переносом на конец короткого месяца.
Сборка и запуск тестов описаны в [README](../../README.md).
