# Сервер приложения

`src/apps/server/src/`: main.cpp связывает QCoreApplication, часы, настройки,
NetworkServices и ServerRuntime. Цель msa_server_support содержит проверяемую
связку приложения; это часть apps/server, не новый слой. Правила — решение 49.

## Запуск и настройки

`msa_server --config <path>` читает строгий JSON через readServerSettings.
Неизвестные/пропущенные поля, неверные типы, диапазоны, URL, зона, пустой токен
и оставленные заглушки отклоняются до открытия БД и порта. Технические ошибки
запуска не раскрывают секреты, SQL и адреса. Пример — server.settings.json.example.

Все поля обязательны. port — 0–65535 (0 выбирает ОС); check_interval_ms и HTTP-
тайм-ауты — положительные целые миллисекунды до часа; context_max_chars и
max_response_tokens — положительные целые до 100 миллионов. model может быть
пустым для выбора llama-server, api_key — пустым для работы без Bearer.
URL HTTP(S) без userInfo/query/fragment. user_agent задаётся явно для Nominatim.
Относительный database_path считается от каталога файла настроек; родительская
папка должна существовать. Новые папки сервер не создаёт.

ServerClock использует указанную IANA-зону при переводе системного момента
в местные секунды core. Эта же зона объявляется в auth/get_all.
Контроль кодовых точек контекста не является точной проверкой токенов модели.

## Операции и сохранность

ServerRuntime создаёт все SQLite-репозитории на одном соединении с миграциями.
ensureMainChat атомарно восстанавливает/создаёт ID «Основного» в server_state
версии 13. Исходная таблица chat_selection сохраняется для прежнего библиотечного
API, но сервер её не использует. Каждый адресованный запрос получает собственный
ChatService с явным chat_id. Создание беседы не меняет экраны устройств.

Реализованы методы каталога версии 1 в docs/protocol.md. Чтение не вызывает
модель или проактивные записи. История отбирается страницами из целых сообщений
с проверкой полного исходящего конверта; отдельное слишком большое сообщение
даёт response_too_large. Сейчас для страницы загружается полная история беседы;
SQL-пагинация и ограничение полного снимка в эту версию не входят.

chat.send сохраняет User до LLM; отказ модели/поиска/бюджета возвращает user_saved
и его ID. chat.retry проверяет ID последнего User, повторно получает явный режим
поиска и не дублирует сообщение. Ошибка хранилища возвращает effect=unknown:
перед повтором нужно перечитать данные. Отключение не отменяет переданную операцию.

command.execute разбирает текст на сервере. Успешные изменения и два сообщения
фиксируются вместе; список задач целиком проверяется до записи. Нераспознанный
текст возвращает handled=false без записи и LLM. Маршрут подготавливается вне
транзакции, затем PreparedRoute сохраняется вместе с User и подтверждением.
Кэш кандидатов может обновиться независимо от результата предметной команды.

Предложения адресов принадлежат TCP-сессии; другая сессия не может подтвердить
или отменить их по номеру. Отключение отменяет предложения, включая результат
поиска, завершённого после закрытия. Изменение напоминания проверяет core.

## Потоки и сроки

Слот requestReceived ставит обработку отдельным событием. NetworkServices держит
постоянные QNetworkAccessManager и адаптеры в QThread; запросы и уничтожение
выполняются там же. Nominatim сохраняет общий ограничитель частоты.
Рабочий поток получает копии запросов без репозиториев/соединения SQLite.

Синхронные интерфейсы core ожидают результат через локальный QEventLoop владельца.
ServerRuntime в это время разрешает чтение и отклоняет новые изменяющие/сетевые
операции как busy. Поэтому в приложение не входят одновременно две связки
ConversationService/NavigationService. Завершение возвращается событием владельцу.
При остановке сетевые объекты уничтожаются в рабочем потоке, затем поток завершается.

Перед слушателем просроченные однократные напоминания атомарно становятся Missed.
Таймер проверяет напоминания и события даже во время HTTP. Пакет отметок сроков
сохраняется транзакцией, события отправляются после commit. Приветствие и вечерний
опрос сохраняются в основном чате; публикация приветствия также атомарна с датой.
Проактивные сообщения откладываются, пока выполняется предметная операция.
Доставка событий после обрыва не гарантируется, фоновой очереди воспроизведения нет.

Ошибки callbacks перехватываются внутри приложения и не выходят в цикл Qt.
Настоящие внешние сервисы/модель и качество анализа не проверяются локальными тестами.
Клиентские окна, музыка, голос и Android пока не подключены.

## Тесты

`tests/infra/ServerRuntimeTest.cpp`: настоящий TCP-транспорт и временные файлы
SQLite; адресация и восстановление основного чата, предметные методы, откат
списка и сообщений, повтор после ошибки LLM, поиск/дневник/профиль, права предложений,
ID/атомарность маршрута, страницы истории и размер кадра, опрос, строгие настройки.
Отдельная проверка использует настоящий NetworkServices и задержанный локальный
HTTP-ответ: ping и напоминание работают до ответа, новая запись получает busy.
Внешняя сеть и настоящая модель не нужны. Все тесты запускаются командами README.
