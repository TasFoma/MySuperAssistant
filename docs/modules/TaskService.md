# TaskService

Предметные операции с задачами без Qt, сети и файлов. Зависимости `Clock` и
`TaskRepository` передаются через конструктор и живут дольше сервиса.

## Точки входа

- `addTask` — создаёт незавершённую задачу с временем из часов.
- `updateTask` — меняет название, срок и приоритет, сохраняя ID, время создания и статус.
- `setTaskDone` — устанавливает или снимает завершённость.
- `tasks` — возвращает независимые копии всех задач в определённом порядке.

## Правила

Название содержит минимум одну кодовую точку UTF-8; текст сохраняется без обрезки
пробелов. Необязательная дата проверяется через `year_month_day::ok()`, прошедший
срок допустим. Приоритет — Low, Normal или High. Решение 23 не меняет минимальную
длину заголовков в `CommandParser`.

Сначала идут незавершённые задачи. В каждой группе приоритет убывает, срок
возрастает; задачи без срока располагаются после датированных внутри приоритета.
При равенстве используется ID по возрастанию, как в приветствии.

Неверный ввод и отсутствие изменяемой задачи возвращают `TaskRejection` с причиной.
Успешное изменение возвращает `std::monostate`, создание — назначенный ID.
Технические исключения зависимостей пробрасываются вызывающему коду.
При отказе проверки запись не изменяется. Удаление остаётся операцией репозитория.

## Ограничения и тесты

Сервис пока не связан с парсером, приложениями и доставкой изменений клиентам.
Нет транзакции между поиском и заменой: конкурентные изменения не согласуются
этим сервисом. Уже сохранённые данные при чтении заново не валидируются.

`tests/core/TaskServiceTest.cpp` проверяет создание с фейковыми часами, односимвольные
названия, прошлый срок, отказы без записи, сохранение полей при изменении,
снятие завершённости, отсутствие записи, все уровни сортировки и независимость копий.
