# ReminderService

Сервис предметной логики напоминаний по времени: `msa::core::ReminderService`.
Заголовок — `src/core/include/msa/core/ReminderService.h`, реализация —
`src/core/src/ReminderService.cpp`, тесты — `tests/core/ReminderServiceTest.cpp`.
Зависимости `Clock` и `ReminderRepository` передаются по ссылкам через конструктор.
Они должны жить дольше сервиса. API описан в Doxygen заголовка.

## Операции

- `addTimed`: сохраняет однократное напоминание в статусе `Pending`. Момент строго
  раньше текущего отклоняется с причиной и просьбой выбрать другое время; равный текущему допустим.
- `addRecurring`: первый запуск через заданный интервал от текущего времени.
  Нулевой, отрицательный или непредставимый интервал отклоняется без сохранения.
- `skipMissedOnStartup`: после загрузки хранилища, перед первой проверкой, вызывающая
  сторона помечает прошлые однократные записи `Pending` как `Missed`. Уведомлений нет.
  Равные текущему времени, будущие, уже показанные и повторяющиеся записи не меняются.
- `checkDue`: для записей со сроком не позже текущего времени переводит однократные
  из `Pending` в `Fired`; повторяющиеся переносит на сейчас плюс интервал.
  Пропущенные интервалы не воспроизводятся. Возвращает исходные записи для уведомления,
  только после успешного обновления каждой записи. Порядок не гарантируется.

`ReminderCreationResult` содержит ID либо `ReminderRejection` с текстом причины.
Технические ошибки хранилища пробрасываются исключениями. Исчезновение записи при
обновлении и некорректный сохранённый интервал вызывают `std::runtime_error`.

## Ограничения

Сервис не подключён к приложениям. Таймер, запуск восстановления и доставка уведомлений —
обязанности вызывающей стороны; автоматического запуска в конструкторе нет.
Работа предполагает последовательные вызовы без конкурентного изменения репозитория.
Обновления нескольких записей не образуют транзакцию: при ошибке часть уже может быть
обновлена. Гарантии доставки уведомлений при сбоях пока нет.

Геонапоминания не обрабатываются. Проверка текста, календарь и напоминания о событиях
не входят в этот сервис. Флаг `fired` у однократных и геонапоминаний заменён статусом
`Pending/Fired/Missed`; повторяющиеся по-прежнему хранят следующий срок и интервал.

Тесты проверяют отказы без сохранения, точный срок, однократность, восстановление после
остановки, несколько пропущенных интервалов, сохранение будущих и геозаписей,
а также ошибку некорректного интервала в хранилище. Сборка и запуск — в [README](../../README.md).
