# Озвучка сообщений на ПК

Локальная озвучка по решению 57 использует Qt TextToSpeech и системный голос.
Python, PowerShell, shell-команды и модель Vosk не нужны. Сервер не синтезирует речь.

## Точки входа

- `src/core/include/msa/core/SpeechSynthesizer.h`: speak/stop/setHandler,
  SpeechEvent и состояния Idle/Speaking/Failed, только stdlib.
- `src/infra/voice/include/msa/infra/QtSpeechSynthesizer.h`: адаптер в msa_infra_voice.
  QTextToSpeech создаётся лениво при первом speak; конструктор не включает звук.
- `src/apps/desktop/include/msa/desktop/SpeechController.h`: связь с VoiceModel,
  остановка речи перед началом диктовки и отмена активной диктовки перед озвучкой.
- `VoiceModel`: speak/stopSpeech, speaking и диагностика без зависимости от infra.
- `MessageBubble` испускает speakRequested; ChatScreen передаёт текст в модель.
  DesktopRuntime владеет адаптером/контроллером и останавливает речь при закрытии.

## Поведение

Кнопка «Озвучить» у сообщения запускает чтение только по действию пользователя.
Новая фраза заменяет прежнюю, «Остановить речь» прерывает синтез и очищает ожидающий
текст. Обновление списка сообщений само по себе ничего не озвучивает. Загруженные
сообщения читаются без сервера; черновик и предметные данные не изменяются.

Инициализация и чтение Qt асинхронны; пока движок готовится, хранится только последняя
фраза. Отмена отбрасывает её, отложенный callback не начинает отменённую речь.
Предпочтение голоса сохранено: русский мужской, любой мужской, русский, любой.
Используются нормализованные rate=0.2 и pitch=0.02. Это настройки Qt, точное
звучание прежнего SAPI rate=2/SSML зависит от системного движка и не гарантируется.

При отсутствии плагина, системного голоса или ошибке воспроизведения UI показывает
локальную ошибку. Сеть и музыка не сбрасываются. Автоматических повторов нет.
Начало речи отменяет незавершённое распознавание, начало записи останавливает
синтез; автоматического приглушения музыки нет. Во время озвучки состояние доступно
во всех разделах через постоянную модель; кнопка остановки находится в чате.

## Сборка и проверки

Для desktop CMake требует компонент Qt6::TextToSpeech; Android пока его не требует.
Используется полный Qt 6.10.3 MSVC 2022 64-bit с Speech/Multimedia. В системе должен
быть доступен голос; установка Qt Speech сама по себе не устанавливает русские голоса.

`tests/infra/src/VoiceModelTest.cpp` проверяет FakeSpeechSynthesizer как вторую
реализацию интерфейса: явное чтение, замену текста, остановку, взаимное исключение
с диктовкой, ошибку, сохранение черновика и завершение контроллера. Отдельный тест
настоящего QtSpeechSynthesizer с отсутствующим плагином проверяет отказ без звука.
`DesktopScreensTest.cpp` проверяет кнопки на загруженном сообщении без сервера,
отсутствие автоозвучки/серверных запросов и рендер speech-output-preview.png.

Автотесты не проигрывают слышимую речь. Выбор голоса на конкретном ПК, слышимость,
произношение и настоящее устройство ввода/вывода проверяются пользователем вручную.
API Qt: [QTextToSpeech](https://doc.qt.io/qt-6/qtexttospeech.html).

## Вывод звука

Устройство выбирается через [AudioDevices](AudioDevices.md). Системный вариант
оставляет штатный движок Qt. Явный вывод на Windows создаётся платформенной
фабрикой Qt WinRT с параметром audioDevice; SAPI такой параметр не поддерживает.
Смена устройства останавливает речь и пересоздаёт движок при следующем действии.
Недоступное выбранное устройство возвращает ошибку без скрытого системного вывода.
