# Локальный сценарий спорта

## Точки входа

SportJournalModel в ui/common владеет SportProgramEditor, SportWorkoutEditor,
текущими программами/черновиками, историей и представлением динамики.
SportLibraryModel.journal предоставляет эту модель обоим клиентам.
SportController в apps/common связывает команды с SqliteSportStore;
SportWorkoutFlow.cpp содержит его операции занятий и жизненного цикла.
UI не читает файлы и не выполняет SQL. Новых CMake-целей/зависимостей нет.

Общие SportProgramPanel/SportProgramsList, SportWorkoutPanel и SportResultsPanel
подключены через SportLibraryPanel. SportFormField/SportFormData отвечают за
представление и точный разбор полей. Публичные операции — в заголовках Model/include.

## Программы

Создание нескольких занятий, добавление повторяющихся пунктов, изменение порядка
занятий/упражнений, добавление/удаление подходов, повторения/вес/сторона/условия.
При добавлении повторения остаются пустыми: технический минимум не назначает нагрузку.
Готовность проверяется отдельно от checkpoint. Сырой ввод (включая «1,»)
сохраняется при каждом изменении. Подтверждение SQLite меняет статус сохранения;
обычное закрытие несохранённого черновика блокируется, доступен повтор записи.

Копирование создаёт новые идентичности программы/занятий/пунктов/подходов;
источник отмечается редакцией. Сохранённые снимки не меняются вслед за копией.
Редакторский checkpoint остаётся доступным до публикации новой редакции;
совпадающий с опубликованной редакцией черновик не дублируется в списке.
Базовая редакция правки сохраняется в служебном поле checkpoint: восстановление
не заменяет её новой текущей редакцией, конкурентная запись отклоняется.

## Занятие

Одна незавершённая тренировка на устройство. При старте создаётся снимок плана,
местная дата, исходное смещение UTC и снимок индивидуальных ограничений.
Позднее изменение общих ограничений не переписывает старые занятия. Поля факта не становятся выполнением
без явного подтверждения. Можно добавить подход, пропустить подход/оставшееся
упражнение, выбрать замену. Выполненный факт остаётся у исходного варианта;
замена не меняет программу и не получает перенесённый вес другого упражнения.
Количество подходов и повторения замены пользователь указывает явно.

До сохранения доступны дата, отдельная ручная итоговая длительность, заметки,
независимые необязательные оценки до/после, несколько областей боли/«Другая область»,
новая боль. Никакого автоматического увеличения нагрузки и медицинского допуска.
Краткая техника видна в занятии, полная открывается из исторического снимка карточки.
В активной форме сначала показан факт; условия, дополнительные действия и
необязательная нагрузка собственного веса свёрнуты.
Назад скрывает сохранённое активное занятие, продолжение доступно из раздела спорта.

Checkpoint вводимых строк и подтверждений выполняется сразу. Для времени используются
QElapsedTimer и явные наблюдения core, фоновое наблюдение сохраняется каждые 5 секунд.
Непрерывная фаза таймера компактна, а не отдельная запись на каждый символ.
При applicationStateChanged/aboutToQuit фиксируется уход, при возвращении/старте
новый интервал требует выбора: активность, пауза, ручная активная часть интервала.
Повтор выбора заменяет вклад. Системные отметки не правятся ручными длительностями;
недостоверное время помечается, ручной ноль допустим только для части отсутствия.

## Итоги и динамика

Завершение проверяет все подходы/интервалы, фиксирует последний checkpoint и одной
транзакцией создаёт результат и снимает активную ссылку. Полный пропуск сохраняется
в истории, не участвует в спортивной динамике. Локальный результат не называется
подтверждённым сервером; синхронизации нет.

Результат открывается для чтения; исправление — отдельный режим. До commit история
и динамика используют прежнюю редакцию. Отмена явная, при ошибке ввод остаётся
в форме. Несохранённая правка результата сейчас хранится в памяти и предупреждает
о необходимости сохранить её перед закрытием приложения; автосохранение active
checkpoint не подменяет сохранение редакции результата.

Прогресс строится чистой функцией core по текущим редакциям, без постоянного кэша.
Есть фильтр по упражнению; каждый подход показан с датой/повторениями/смыслом веса
и переходом к занятию. При открытии результата перечитывается текущая редакция.
Стороны, вариант, количество гантелей, режим собственного веса и условия разделены;
неописанная амплитуда не объединяется между занятиями. Универсального тоннажа нет.

## Проверки и текущие границы

SportLibraryTest проверяет редактор, восстановление/отказ и независимые копии.
SportWorkoutFlowTest проверяет путь через реальные модели/apps/временную SQLite,
повторное восстановление/таймер, завершение/исправление, конфликты, пропуски/замены
и настоящие QML-оболочки. Все базы — QTemporaryDir, личный сервер не используется.
Результаты прогонов и снимки фиксируются в README и разделе 16 спортивного ТЗ.

Рабочий контент — 6 из 22 карточек. P1/P3 ещё не опубликованы. Просмотр другого
результата при незавершённом занятии пока отклоняется явно; завершённый результат
можно исправлять. Для Android нужны отдельные проверки реальной IME/фона/завершения
процесса на устройстве: offscreen-рендеры и успешный APK их не заменяют.
