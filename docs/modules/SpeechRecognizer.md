# Голосовой ввод на ПК

Распознавание перенесено на C++ по решению 57. Vosk работает в отдельном
служебном процессе msa_voice_worker, управление и интерфейс остаются в desktop.
Python, sounddevice и PowerShell для распознавания не нужны.
Озвучка через Qt TextToSpeech описана отдельно: [SpeechSynthesizer](SpeechSynthesizer.md).

## Точки входа

- `src/core/include/msa/core/SpeechRecognizer.h`: интерфейс configure/start/finish/
  cancel/shutdown, состояния и события без Qt. Вызовы и обработчик — в потоке владельца.
- `src/infra/voice/include/msa/infra/ProcessSpeechRecognizer.h`: настоящий адаптер
  дочернего процесса, таймеры и проверка сообщений. Конструктор ничего не запускает.
- `VoskDecoder.h` в том же include: RAII над C API, модель и распознаватель новой фразы.
  Линкуется только в msa_infra_vosk и служебный процесс.
- `VoskAudioSession.h`: захват QAudioSource, сбор PCM и распознавание одной фразы
  в infra; QObject-указатели невладеющие, устройство останавливается до удаления модели.
- `src/apps/desktop/VoiceWorker/`: main и VoiceWorker соединяют локальный канал
  с VoskAudioSession. Заголовки в include/msa/desktop, реализации в src.
- `src/ui/common/Model/include/msa/ui/VoiceModel.h`: состояние, действия и черновик.
- `src/apps/desktop/include/msa/desktop/VoiceController.h`: соединение интерфейса core,
  модели UI и отдельного JSON. DesktopRuntime владеет объектами и закрывает запись.

## Жизненный цикл и запись

Выбор папки сохраняет только путь. Модель Vosk не загружается и микрофон не
открывается до явного «Говорить». Первое действие запускает msa_voice_worker и
загрузку модели; после готовности начинается одна запись. Модель остаётся в
процессе между успешно завершёнными записями. Загрузка не блокирует UI.

Как в исходном скрипте, используется PCM 16 кГц, int16, mono. Проверяются наличие
микрофона, поддержка формата и ошибки QAudioSource. Первая законченная непустая
фраза завершает запись; «Завершить запись» возвращает FinalResult накопленного аудио.
Целые сэмплы собираются из произвольных фрагментов QIODevice. Аудио обрабатывается
короткими порциями; при переполнении ограниченного буфера запись завершается ошибкой.

Родитель ограничивает загрузку 120 с, запись 30 с, ожидание завершения 2 с.
По истечении записи запрашивает FinalResult; если процесс не отвечает, завершает
его. «Отменить запись», смена модели и закрытие приложения отбрасывают незавершённое
распознавание и останавливают процесс. Отмена действует и во время загрузки модели.
Автоматического перезапуска и повторения записи нет: следующий запуск только явный.
Завершение по лимиту сохраняет FinalResult и отдельно сообщает о лимите времени,
не запрещая следующую явную запись.

Поколение процесса и положительный ID записи защищают от поздних сообщений.
Подтверждённый текст добавляется в черновик в C++, сохраняя уже введённый текст.
Черновик можно редактировать без сервера и без выбранной беседы; кнопка отправки
остаётся отключённой до готовой сессии и выбора чата. Распознаватель никогда
сам не отправляет текст серверу. Черновик хранится только в памяти процесса.
Ошибка голоса отделена от ошибки сети и не сбрасывает музыку или серверные данные.

## Локальный канал процесса

Родитель создаёт QLocalServer со случайным именем и UserAccessOption и передаёт
имя через `--channel`. После первого соединения слушатель закрывается. QLocalSocket
используется для асинхронного обмена; путь модели передаётся внутри канала.
Это внутренний протокол, не клиентский TCP-протокол ассистента.

VoiceProtocol кодирует UTF-8 JSON-объекты с version=1, type и LF. Предел кадра —
64 КиБ; неполные UTF-8/JSON накапливаются до LF. Версия и схемы известных сообщений
проверяются, чужая запись не применяется. session — положительная десятичная строка.

- Родитель → worker: load с model; start/finish с session.
- Worker → родитель: ready; text с session/text; done с session; error с message.

Шумные stdout/stderr библиотек отделены от канала и не выводятся в интерфейс.
Worker не закрывает канал сразу после ошибки: родитель должен сначала получить
диагностику. Отмена/ошибка останавливает дочерний процесс без ожидания в UI.
При уничтожении адаптер ограниченно дожидается уже завершавшихся процессов.

## Настройки и сборка

voice.settings.json версии 1 содержит ровно version и model_path: пустую строку
или абсолютный путь к распакованной папке модели. Максимум — 64 КиБ, запись через
QSaveFile атомарная. Ошибка чтения не переписывает файл; неудачная запись не меняет
применённую папку. По умолчанию файл рядом с client.settings.json; путь можно
переопределить в DesktopRuntimeOptions. Пример — voice.settings.json.example.

Пакет Windows x64 Vosk 0.3.45 автоматически получает CMake из официального GitHub;
URL и SHA256 закреплены в cmake/Vosk.cmake. Пакет включает C API, import library и
DLL; четыре runtime DLL копируются рядом с msa_voice_worker. Vosk распространяется
под Apache-2.0. Клиентский процесс и сервер Vosk не линкуют. В исходники проекта
DLL не добавляются. Саму языковую модель CMake и приложение не скачивают:
пользователь выбирает свою распакованную модель, включая ранее использовавшуюся.

Нативный worker пока собирается только для Windows x64. Интерфейс core, модель UI
и управление процессом не содержат Windows API. Android остаётся этапом 8.

## Проверки и ограничения

SpeechRecognizerTest.cpp и отдельный FakeVoiceWorker проверяют настоящие локальные
каналы/процессы: кадры, разрыв UTF-8, большие ID, загрузку по действию, повторную
запись, ручное/автоматическое завершение, отмену, чужую сессию, сбой, сроки и
отсутствие автоматического повтора. Настоящий msa_voice_worker проверяется с
отсутствующей моделью: загружается согласованная DLL, возвращается контролируемая
ошибка без открытия микрофона.

VoiceModelTest.cpp использует вторую реализацию SpeechRecognizer — FakeSpeechRecognizer:
проверяет JSON, ошибки файлов, URI/Unicode, добавление к черновику и действия.
DesktopScreensTest.cpp проверяет клавиатурные кнопки и обновление поля без связи,
отсутствие автоотправки при готовом сервере и минимальный размер окна. Рендеры:
voice-input-preview.png и voice-input-minimum-preview.png. Полный текст голосовой
ошибки доступен в подсказке компактной строки. Сборка/CTest — командами из README.

Тесты не открывают микрофон, не читают личную модель и не проверяют качество
распознавания настоящей речи. Формат устройства должен поддерживать указанный PCM;
преобразования из других форматов пока нет. Системный микрофон и большую модель
нужно проверить пользователю отдельно. Голосовой ввод и озвучка используют разные
контракты; SpeechController в приложении исключает их одновременную работу.
