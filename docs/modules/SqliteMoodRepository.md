# SqliteMoodRepository

SQLite-реализация `core::MoodRepository` по решениям 31 и 40. Хранит все явные
записи дневника с полным исходным текстом, без очистки по возрасту.
Заголовок — `src/infra/include/msa/infra/SqliteMoodRepository.h`, реализация —
`src/infra/src/SqliteMoodRepository.cpp`.

## Схема и точки входа

Конструктор принимает невладеющую ссылку на SqliteDatabase со всем списком
`sqliteMigrations()`. База живёт дольше репозитория; все операции используют
её соединение в потоке владельца при живом QCoreApplication. Приложения пока
не создают репозиторий.

Миграция 7 создаёт `mood_entries`: INTEGER PRIMARY KEY AUTOINCREMENT, местные
секунды recorded_at, оценка score (-1, 0, 1) с CHECK и полный текст note.
Часовой пояс не преобразуется. Пустые заметки, повторы, пробелы, переносы,
Unicode и встроенный NUL сохраняются; ограничения длины нет.

`add` принимает запись с нулевым ID, назначает положительный ID, не меняя
исходник. Неизвестная оценка и ненулевой входной ID вызывают std::invalid_argument
до записи. `all` возвращает независимые копии всех записей без гарантии порядка.
Технические ошибки и неизвестная сохранённая оценка — std::runtime_error,
а не пустой дневник. Период и сортировку применяет MoodService.

## Связь с профилем и миграция

Версия 7 пересоздаёт `profile_facts` с внешним ключом source_mood на mood_entries.
Сначала копирует факты и теги во временные по имени таблицы, затем заменяет
прежние. ID, порядок, тексты, теги, приоритет, источники и взаимные ссылки версий
сохраняются. foreign_keys остаётся включённым; вся миграция выполняется в общей
транзакции SqliteDatabase. Переименование обновляет ссылки новых таблиц.

Существующая ненулевая ссылка на отсутствующий дневник отклоняет обновление:
откатываются и создание таблиц, и перенос, и номер версии. Исходный файл остаётся
читаемым со старым списком миграций. Записи дневника не синтезируются, источники
не обнуляются. Старые версии приложения ещё не создавали дневник на диске;
штатные ручные и автоматические факты без записи настроения имеют NULL в source_mood.
Это обновление новой схемы проекта, импорта базы старого проекта нет.

Запись профиля с отсутствующим ID дневника и удаление используемой записи
отклоняются внешним ключом. Источник остаётся необязательным.

## Атомарность и ограничения

Добавление — один подготовленный INSERT, участвующий во внешней транзакции.
Дневник и профиль можно сохранить или откатить вместе; User, записанный до
транзакции, остаётся. ConversationService использует TransactionRunner для общей
записи дневника, профиля, Assistant и снятия ожидания; всем репозиториям передаётся
один владелец базы. Конкурентные изменения профиля не поддерживаются.
Весь дневник читается в память; постраничной выборки и запросов по периоду нет.

## Тесты

`tests/infra/SqliteMoodRepositoryTest.cpp`: семь файловых тестов. Обновление с
версии 6 сохраняет версии профиля, порядок, теги и источники; неверная старая
ссылка полностью откатывает миграцию. Проверяются повторное открытие, постоянные
ID, все оценки, отрицательное время, полный длинный UTF-8 текст с NUL, копии,
пустые/повторные заметки, неверный ввод, SQL-ошибки, внешний ключ дневника и общий
откат с профилем. MoodService с FakeClock проверяет период, порядок и сохранность
старых/будущих записей после открытия заново.
Команды — в [README](../../README.md).
