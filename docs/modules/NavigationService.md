# NavigationService и контракты внешних сервисов

Навигация и сводка погоды в `core` без Qt и сети. Сохранение расчётов передано
RouteHistoryService, который получает часы и репозиторий через конструктор.
Поведение согласовано решениями 42–43; HTTP-реализации — в
[ExternalServices](ExternalServices.md).

## Точки входа

- `Geocoder::search` — кандидаты по названию; Unicode-trim запроса, проверка
  полных названий и координат. Пустой ввод — InvalidRequest, отсутствие — NotFound.
- `RoutePlanner::route` — маршрут по двум точкам и TravelMode из Command.h.
  Проверяет координаты, режим, конечные неотрицательные метры/секунды и манёвры.
- `WeatherProvider::forecast` — погода по явной точке, проверки текущих и
  необязательных дневных показателей.
- `NavigationService::routeFrom` — маршрут от явных координат до места по названию.
- `NavigationService::routeBetween` — оба конца по названиям, с явной опорной
  точкой для поиска ближайших кандидатов.
- Конструктор NavigationService получает Geocoder, RoutePlanner и обязательный
  RouteHistoryService. Успешный расчёт сохраняется до возврата; технический отказ
  истории пробрасывается без автоматического повтора.
- `routeText`, `weatherText` — русское представление уже проверенных данных.
- `validCoordinates`, `geographicDistance` — проверка координат и расстояние
  по сфере радиусом 6 371 000 м, с защитой вычислений для противоположных точек.

Публичные заголовки находятся в `src/core/include/msa/core/`, реализации —
`src/core/src/Geocoder.cpp`, `RoutePlanner.cpp`, `WeatherProvider.cpp`,
`NavigationService.cpp`. Подробности типов — в Doxygen заголовков.
Все нешаблонные реализации и виртуальные деструкторы находятся в .cpp.

## Как работает

Интерфейсы получают один полный ответ от реализации, проверяют его и возвращают
`ExternalServiceResult<ValueType>`: значение либо ExternalServiceError.
InvalidRequest означает неверный ввод, NotFound — отсутствие места/маршрута,
Unavailable — недоступность, InvalidResponse — неверные данные поставщика.
Автоматических повторов нет. Ошибки памяти/реализации могут быть исключениями;
ServerRuntime перехватывает их на границе предметной операции без раскрытия технического текста.

Координаты всегда передаются явно; (0, 0) — допустимая точка. Неизвестное
местоположение нельзя обозначать нулями: приложение должно запросить место
или координаты. Геолокация телефона и её хранение пока не подключены.

Геокодер возвращает кандидатов без выбора города. NavigationService выбирает
минимальное расстояние по сфере до опорной точки; при равенстве остаётся первый
кандидат поставщика. Для routeFrom опорная точка совпадает со стартом, для
routeBetween оба названия ищутся относительно переданного reference.

Далее для Foot/Bike проверяется расстояние по прямой: строго больше 200 км —
отказ до OSRM. При меньшем расстоянии либо Driving вызывается RoutePlanner.
При Unavailable сервис возвращает RoutePlan с approximate=true, без манёвров:
расстояние по сфере × 1.3, длительность по скорости 5/15/40 км/ч.
NotFound и InvalidResponse не заменяются приблизительным маршрутом.
В тексте такой результат явно назван приблизительной оценкой.

Русские инструкции включают начало, прибытие, повороты и круговое движение;
для пешего режима используется «пройдите», для остальных — «проедьте».
Если номер съезда отсутствует, даётся общая инструкция кругового движения;
1-й съезд не подставляется. Неизвестный код WMO обозначается как «состояние
погоды не определено». Оба исправления подтверждены решением 42.
Метры округляются до десятков, километры — до десятых; минуты — минимум одна,
от часа показываются часы и остаток минут. Длительность — прогноз, а не
результат измерения скорости пользователя; персонализации по прогнозам нет.

Сводка погоды содержит округлённую температуру и ощущаемую температуру,
описание WMO и, если доступны, минимум/максимум текущего местного дня.
Дневные экстремумы не выдаются за отдельный прогноз дня/ночи.
От 30% осадков добавляется предложение взять зонт. Дневные показатели
необязательны; минимум и максимум принимаются только вместе.
Ветер сохраняется в типизированном результате, как в запросе старого клиента,
но не добавляется в короткий текст сводки.

## Ограничения и тесты

Успешный routeFrom/routeBetween возвращает calculationIdentifier назначенной
записи истории. prepareFrom возвращает PreparedRoute без записи истории:
план и исходные данные расчёта можно сохранить через RouteHistoryService вместе
с сообщениями команды одной транзакцией. ServerRuntime использует это для
command.execute; поиск и маршрутизация не держат транзакцию SQLite.

История расчётов и статистика реализованы в [RouteHistoryService](RouteHistoryService.md),
кэш кандидатов — в [CachedGeocoder](CachedGeocoder.md), подтверждение точки —
в [PlaceReminderLocationService](PlaceReminderLocationService.md). GPS телефона
пока не подключён. Сервер передаёт явные координаты/настройки. Сама связка core не вызывает UI,
протокол, приветствие или чат. Названия для routeText передаёт вызывающий код;
результат NavigationService содержит маршрут без текстовых меток начала/конца.

`tests/core/NavigationServiceTest.cpp` использует тестовые Geocoder,
RoutePlanner и WeatherProvider. Проверяются выбор места, переход долготы ±180°,
границы координат, отказы до внешнего вызова, режимы, порог 200 км,
приблизительная оценка, проверки результатов и русское форматирование.
Файлы, сеть, Qt и реальные часы не нужны.
