# TcpServer

TCP-транспорт [протокола версии 1](../protocol.md), реализованный по
[решению 48](../decisions.md). Находится в `src/infra/include/msa/infra/TcpServer.h`
и `src/infra/src/TcpServer.cpp`. Использует Qt Network, существующий ProtocolCodec
и Clock из core; предметных операций, SQLite и HTTP-запросов не выполняет.

## Точки входа

- Конструктор получает явные токен, IANA-зону и часы местного времени; создаёт
  server_instance_id. Пустой токен и неизвестная зона отклоняются без вывода значений.
- `listen` принимает адрес/порт; `serverPort` возвращает фактический порт.
- `requestReceived(connectionId, request)` передаёт проверенный запрос обработчику.
- `sendResponse` принимает успех либо отказ только для ожидающего запроса указанной
  сессии. Неверный конверт, чужой/завершённый ID или закрытая сессия дают false.
- `publishEvent` проверяет событие и рассылает авторизованным соединениям с общими
  server_instance_id/event_id; приложение вызывает его после успешной записи.
- `connectionClosed` освобождает временные предложения вызывающей стороны.
- `close` останавливает слушатель и закрывает сессии; повторный listen сохраняет
  server_instance_id и не переиспользует прежние connectionId.

## Сессия и обмен

У каждого сокета собственные накопитель кадров, одноразовый таймер авторизации,
множество использованных request_id и множество запросов, ожидающих ответа.
Первый кадр — только auth. На неподдерживаемую версию/неверный токен возвращается
коррелированный отказ и соединение закрывается. Незавершённый auth также должен
уложиться в 10 секунд. После успеха таймер останавливается, повторный auth отклоняется.

Кадры разбираются последовательно, включая несколько строк в одном блоке и разрывы
UTF-8. Сокет читается блоками до 64 КиБ; его входной буфер и накопитель ограничены.
Фатальный кадр закрывает сессию и запрещает исполнение следующих кадров этого блока.
Хвост без LF после EOF никогда не исполняется. Ошибка параметров/метода с надёжным
request_id получает коррелированный отказ и оставляет авторизованную сессию открытой.
ID таких отказов и auth тоже запоминаются; повтор ID не передаётся обработчику.

Ответы могут завершаться в другом порядке, чем запросы. После первого успешного
завершения ID удаляется из ожидающих, но остаётся использованным до отключения.
Закрытие сессии делает её поздние ответы недействительными; данные операции
от этого не откатываются. true от sendResponse означает постановку в сокет,
а не получение ответа клиентом. Автоматического повтора/журнала идемпотентности нет.

Слишком большой ответ заменяется response_too_large с исходным request_id без
обрезки текста. Для успеха effect=unknown: транспорт не знает, были ли записи.
Для отказа сохраняются effect и user_message_id обработчика. Неверное или слишком
большое событие не отправляется. События не хранятся для воспроизведения.

Исключение непосредственного обработчика запроса превращается в storage_error с
effect=unknown без технического текста; исключение уведомления о закрытии подавляется
после очистки сессии. Queued-обработчик сам перехватывает свои исключения: они уже
не находятся в стеке транспорта.

## Потоки и ограничения

Нужен QCoreApplication с работающим циклом событий. Все методы и сокеты принадлежат
одному потоку; часы живут дольше транспорта. Сигнал не делает долгую функцию
асинхронной: слот должен передать работу исполнителю и быстро вернуться.
Завершение из рабочего потока следует поставить в очередь потока TcpServer через
QMetaObject::invokeMethod с контекстом сервера. Нельзя передавать существующее
SQLite-соединение в произвольный поток. Связка приложения реализована в
[ServerRuntime](ServerRuntime.md) по решению 49: HTTP в рабочем потоке,
SQLite и завершения в потоке владельца.

Обработчик обязан сформировать один итоговый ответ, проверить предметные права/состояние
и передать достоверный effect. Транспорт не выполняет даже get_all/ping самостоятельно.
Запись в сокет не гарантирует доставку, отключение не отменяет сохранённую операцию.
В этой версии нет общего лимита авторизованных соединений, накопленных ID и очереди
исходящих данных; предел одного кадра не является защитой от перегрузки сервера.
Предметные операции подключены в apps/server. Настоящие клиенты и Tailscale
пока не проверены.

## Тесты

`tests/infra/src/TcpServerTest.cpp`: локальные сокеты без внешних сервисов. Проверяются
авторизация и реальный десятисекундный тайм-аут, ошибки/повторы ID, параметры,
фрагментация UTF-8 и склейка кадров, предел и повреждение кадров, запрет клиентских
ответов, несколько сессий и порядок завершения, EOF/переподключение/поздний ответ,
рассылка событий, большой ответ, queued-обработчик, исключения и повторный listen.
Тестовый обработчик не обращается к БД или модели.
