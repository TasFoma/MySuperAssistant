# ChatService

`msa::core::ChatService` управляет текущим чатом и полной сохранённой историей.
Заголовок — `src/core/include/msa/core/ChatService.h`, реализация —
`src/core/src/ChatService.cpp`. Правила — решения 33–34. API описан в Doxygen заголовков.
Clock и ChatRepository передаются невладеющими ссылками и должны жить дольше сервиса.

## Данные и точки входа

- `Chat` — ID, название в UTF-8 и местное время создания с точностью до секунд.
- `ChatMessage` — ID, ID чата, роль MessageRole (User/Assistant), полный текст
  и местное время записи с точностью до секунд.
- Конструктор ChatService восстанавливает сохранённый выбор, если чат существует.
  Иначе выбирает максимальный ID из списка, а при пустом списке создаёт новый чат.
  Исправленный выбор сохраняется в репозиторий; ошибки не маскируются пустым чатом.
- `newChat` создаёт чат с названием «Чат от ДД.ММ.ГГГГ ЧЧ:ММ» по времени Clock,
  сохраняет выбор и только затем меняет currentChatId сервиса.
- `chatList` возвращает копии чатов по убыванию ID.
- `switchChat` сохраняет выбор существующего чата; при отсутствии возвращает
  ChatRejection с причиной без смены текущего чата.
- `addMessage` проверяет роль и непустоту текста после мысленного удаления
  пробельных символов Unicode по краям. В хранилище передаётся исходный полный
  текст, без обрезки и нормализации. Пустые и пробельные сообщения отклоняются.
- `loadMessages` возвращает копии всех сообщений текущего чата по возрастанию ID.
  Время используется как данные, а не как ключ порядка: откат часов не меняет историю.
- `historyMessages` отбирает непрерывную последнюю часть сохранённой истории
  текущего чата. Бюджет задаётся явно в кодовых точках Unicode и учитывает только
  текст сообщений. Сообщения включаются целиком от последнего к более ранним;
  при первом непоместившемся отбор останавливается. Результат — копии по возрастанию ID.
  Если последнее сообщение не помещается, возвращается ChatRejection с причиной.
  Пустая история даёт пустой список, в том числе при нулевом бюджете. Отдельного
  предела в 40 сообщений или 4000 символов нет. Вычитание из оставшегося бюджета
  не требует суммирования длин с риском переполнения.

## Хранилище и ошибки

ChatRepository объявлен в `src/core/include/msa/core/ChatRepository.h`, деструктор —
в `src/core/src/ChatRepository.cpp`. Он хранит чаты, сообщения и выбранный ID.
Добавление принимает запись с нулевым ID, назначает положительный ID и сохраняет копию.
Чтение возвращает копии; списки не гарантируют порядок. Отсутствующий чат при поиске
даёт nullopt, при чтении сообщений — пустой список. Добавление сообщения отсутствующего
чата даёт nullopt, сохранение неверного выбора — false без изменения выбора.
Загруженный извне выбранный ID может указывать на отсутствующий чат, сервис исправляет его.

Сервис возвращает отказы для пользовательских ошибок, технические исключения
пробрасывает. Исчезновение только что созданного или выбранного при восстановлении
чата вызывает runtime_error. Создание чата и сохранение выбора не образуют транзакцию:
если первый шаг успешен, а второй завершился ошибкой, новый чат остаётся в списке,
но выбор сервиса и ранее сохранённый выбор не меняются. При ошибке конструктора
объект сервиса не создаётся. Автоматического отката или удаления чата нет.

## Ограничения

Реализация InMemoryChatRepository находится в `tests/core`, её данные живут только
в памяти процесса. [SqliteChatRepository](SqliteChatRepository.md) в infra сохраняет
чаты, полные сообщения и текущий выбор на диске; миграция схемы — версия 2.
Приложения пока не создают ChatService. Конструктор читает и при необходимости
изменяет хранилище, поэтому может бросить исключение.

Предполагается последовательная работа одного ChatService с хранилищем; внешняя смена
сохранённого выбора не обновляет локальный currentChatId существующего сервиса.
Одновременная работа клиентов и сообщения протокола относятся к этапу 5.
Чтение сообщений сейчас получает все сообщения одного чата, без постраничной загрузки.

Редактирование, переименование и удаление чатов или сообщений не добавлены.
Автоматической очистки истории и ограничения её длины нет. Отбор последних сообщений
не удаляет исходные данные. Бюджет символов не является бюджетом токенов модели;
роли, шаблон чата и прочие служебные части запроса в него не входят.
Метод включает все подходящие сохранённые сообщения, включая последнее;
LlmContextBuilder исключает текущую запись по ID, если вопрос уже сохранён.
Готовые историю, выбранные факты и сводку можно передать в
[LlmContextBuilder](LlmContextBuilder.md) для общей сборки без записи в хранилище.
MentorPrompt и обработка типизированного ответа в ConversationService реализованы
и проверены с тестовым клиентом. Предложения фактов из того же ответа сохраняются
в профиль с источником и версиями. HTTP и анализ настоящей моделью пока отсутствуют.
Ограничения контекста не должны удалять
исходную переписку.

## Тесты

`tests/core/ChatServiceTest.cpp` содержит тесты сервиса и контракта репозитория:
первый запуск и повторное создание сервиса, сохранённый выбор, отсутствующий выбор
и устаревший ID, создание и переключение чатов, порядок независимо от порядка
списков репозитория и перевода часов, раздельные истории, независимые копии,
пустые и пробельные сообщения Unicode, неизвестная роль, длинный полный текст,
повторные записи и история длиннее 40 сообщений, ошибки чтения и записи,
состояние после отказа сохранения выбора и отсутствие сообщений без чата.
Тесты отбора истории проверяют точную границу бюджета, непрерывность последней
части без пропуска большого сообщения посередине, Unicode (кириллица, emoji,
комбинируемый знак), нулевой/недостаточный/максимальный бюджет, сохранение ролей,
времени и полного текста, текущий чат, независимость копий, отсутствие отдельных
лимитов 40/4000 и распространение ошибки чтения без изменения сохранённых данных.
Время задаёт FakeClock; файлов и сети нет. Команды — в [README](../../README.md).
