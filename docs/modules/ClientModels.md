# Типизированные клиентские модели

По решению 51 UI принимает типы core, а JSON разбирается только в infra.
Публичные объявления содержат Doxygen; этот документ описывает связку и ограничения.

## Данные и граница протокола

`src/core/include/msa/core/ClientData.h` содержит ClientSnapshot, результаты чтения,
страницу истории, запросы чтения и пользовательские действия. Только stdlib и
существующие предметные типы, без Qt, JSON, файлов и сети. Это структуры передачи
данных, не новый абстрактный сетевой интерфейс.

`src/infra/include/msa/infra/ClientProtocol.h` и `src/infra/src/ClientProtocol.cpp`
кодируют восемь видов чтения и полностью декодируют результаты: get_all, chat.list,
chat.messages, calendar.day/month, profile.get, mood.history, route.history.
Проверяются обязательные/лишние поля, типы, строковые int64 ID, перечисления,
календарные значения, nullable поля, вложенные предметные объекты и дубли ID.
Сравнение обратной сериализации с исходным объектом исключает неизвестные поля
и молчаливые значения по умолчанию. Ошибки — invalid_argument без тела JSON.

Страница истории проверяется вместе с исходным запросом: адрес беседы, предел,
возрастание ID, отсутствие дубликатов, next_after_message_id и продвижение при
has_more. Весь результат строится до передачи в UI; неверный элемент не заменяет
часть списка. Текст и ID не сокращаются и не преобразуются в неточные числа JS.

Типизированные действия этого шага: завершённость задачи, создание беседы,
отправка сообщения с необязательным поиском и явный retry с ID User. Кодек
проверяет их запросы и подтверждения. Остальные формы действий, маршрутизация,
погода и выбор адреса подключаются при реализации соответствующих экранов;
серверные методы и их протокол этим шагом не меняются.

## Модели ui/common

`ClientListModel.h/.cpp` и `ClientModels.h/.cpp` находятся в
`src/ui/common/include/msa/ui/` и `src/ui/common/src/`.
ClientListModel — QAbstractListModel с именованными ролями, count и stale.
Чтение отмечает соответствующий список устаревшим до принятия свежего результата;
ошибка обновления не выдаёт прежние данные за новые.
Виды списков: задачи, напоминания, привычки, вхождения событий, беседы,
сообщения, профиль, дневник, расчёты маршрутов. Для событий дня отдельный список
calendarEvents, для текущей даты — eventsToday. Статистика маршрутов и дни месяца
доступны отдельными свойствами ClientModels.

ID всех записей в ролях представлены строками identifier. Необязательные поля
имеют невалидный QVariant, а нулевые координаты остаются нулями с hasCoordinates=true.
Время — строка местной шкалы сервера, timezone хранится отдельно. Модели не
считают повторы, прогресс привычек или статистику: показывают значения сервера.
Неверный тип строки, неположительный/повторный ID отклоняет замену списка целиком.

ClientModels владеет списками и предоставляет свойства подключения, ошибок,
выбранной беседы и страниц. online/serverActionsEnabled становятся true только
при Ready транспорта и принятом снимке текущей сессии. При обрыве строки остаются
в памяти, stale=true; действия не отправляются и не ставятся в очередь.
Текст «нет связи», Exhausted и запрос ручного reconnect доступны будущему экрану.

Выбор беседы локальный и разрешён без связи для загруженной библиотеки.
Модель хранит уже загруженные сообщения по chat_id в памяти. Новая сессия и
изменение выбора имеют разные ревизии: ответ прежней сессии/экрана не заменяет
текущую беседу. Страницы добавляются только к ожидаемому курсору; повтор страницы
не дублирует строки. Первый свежий запрос после переподключения заменяет прежний
снимок истории, выбор экрана остаётся прежним. Первый чат сам не выбирается.

Ошибки user_saved и unknown сохраняются вместе с ID исходника/последствиями;
фоновый отказ чтения не затирает их. Только явный retry соответствующего User
после успешного подтверждения убирает user_saved; автоматического retry нет.
Для поиска вызывающая сторона передаёт прежнюю фразу повторно.

## Связка приложения

`src/apps/desktop/src/DesktopClientController.h/.cpp` соединяет TcpClient и
ClientModels. Проверяемая библиотека msa_desktop_support принадлежит apps/desktop,
не добавляет нового слоя. UI линкуется только с core и Qt Quick; QObject моделей
не знает ни адреса сервера, ни методов протокола, ни QJsonObject.

Контроллер создаётся с зависимостями до запуска клиента и сам сеть не включает.
После ready он передаёт снимок декодеру и моделям, затем загружает библиотеку бесед,
профиль, дневник и историю маршрутов. События объединяются в отложенное чтение.
При повторных чтениях одной области применяется только самый новый запрос.
Обычная ошибка чтения не вызывает новый цикл чтений; успешное действие вызывает
обновление данных без оптимистической записи в UI.

При неверном содержимом ответа контроллер отключает сессию и сохраняет последние
данные. Неверное подтверждение записывающего действия получает unknown: отсутствие
достоверного ответа не доказывает откат. user_saved/unknown из ошибок передаются моделям; старые запросы не
воспроизводятся при Ready. Соединения обработчиков ограничены временем жизни
контроллера. Создание окна и загрузка личных настроек пока не добавлены в main.

## Проверки и оставшиеся части

`tests/infra/ClientModelsTest.cpp`: строгий разбор и отклонение неверных вложенных
данных, источники профиля, календарь, маршруты, точность ID, nullable/нулевые
координаты, QAbstractListModel, страницы/ревизии, просмотр без связи, отсутствие
серверных действий и приоритет ошибки неизвестной записи. Невизуальный QQmlComponent
читает свойства и проверяет bindings без запуска окна. Сокетная связка с TcpServer
проверяет обновление по подтверждению, повреждённые данные, отсутствие бесконечных
чтений и защиту от старого снимка, пришедшего после нового.

`tests/infra/ServerRuntimeTest.cpp` дополнительно проверяет всю цепочку
ClientModels → DesktopClientController → TcpClient → ServerRuntime → SQLite/LLM:
получение user_saved, явный retry без второго User, история и её сохранение без связи.
Сеть внешних поставщиков, настоящая модель и UI-экраны не используются.

Кэш пока только в памяти процесса. Формат постоянных настроек клиентов,
QML-компоненты/тема, пользовательские экраны и остальные формы действий относятся
к следующим шагам плана. Команды сборки и тестов — в [README](../../README.md).
