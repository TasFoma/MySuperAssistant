# Тестовый клиент и проверка процесса сервера

`tests/infra/ProtocolTestClient.h/.cpp` содержит независимый TCP/JSON-клиент
проверок протокола версии 1. Он формирует конверты через Qt JSON без серверных
ProtocolCodec/ProtocolPayload, сохраняет перемежающиеся ответы и события и
выбирает ответ по request_id. Это тестовый помощник, не сетевой адаптер desktop/mobile.

## Точки входа

connectTo открывает новую сессию и сбрасывает её кадры; authenticate выполняет
auth. request передаёт одну операцию и ждёт её ответа, sendRequest отделяет
отправку от ожидания. response не теряет ответы других запросов или события.
sendBytes позволяет передавать неполные кадры и разрывы UTF-8. disconnect
немедленно закрывает соединение; повторную запись клиент не выполняет.
frames хранит целые кадры новой сессии для поиска чужих поздних ответов.
Подробности API — в Doxygen заголовка.

## Как проверяется сервер

`tests/infra/ServerProcessTest.cpp` запускает собранный msa_server отдельным
QProcess с --config. CMake передаёт путь исполняемого файла через определение
тестовой цели и гарантирует его сборку до msa_infra_tests. Каждый тест
создаёт временные JSON-настройки и SQLite-файл, слушатель использует порт 0.
Тест считывает фактический TCP-порт из сообщения запуска процесса.
Для дочернего процесса задаётся QT_FORCE_STDERR_LOGGING=1: Qt-журнал должен
попадать в перенаправленный stderr QProcess, включая сообщение о готовности.

LocalModelServer принимает настоящий HTTP-запрос модели, ждёт получения полного
тела по Content-Length и удерживает ответ до явного действия теста. Это позволяет
обрывать TCP-клиента в нужной фазе без гонки с таймером или настоящей моделью.
Поставщики данных заменены локальными адресами, личные настройки не используются.
После проверки тест останавливает свой процесс; временная база удаляется вместе
с каталогом теста. Пользовательские процессы и файлы не затрагиваются.

Сценарии:

- Потерянное подтверждение command.execute: независимый наблюдатель доказывает
  commit, исходный клиент не читает ответ. После переподключения он перечитывает
  задачи/историю без повторной записи. Перезапуск процесса сохраняет данные,
  ID основного чата и меняет server_instance_id.
- Обрыв во время LLM: новая сессия повторно использует прежний request_id для
  ping, читает сохранённый User и получает busy на новую запись. Поздний ответ
  сохраняется в исходном чате, но не отвечает вместо ping новой сессии.
- Ошибка модели: user_saved с ID исходника, переподключение, проверка истории и
  ожидаемого ID, затем только явный chat.retry. Второго User и скрытого запроса
  модели нет; повтор после уже сохранённого Assistant отклоняется.
- Неверный токен, EOF на части UTF-8/JSON, завершение фрагментированного кадра,
  повтор request_id и неизвестный метод: отсутствует частичная/повторная запись,
  после обычного отказа сессия остаётся пригодной для чтения и изменения данных.

## Ограничения и запуск

Проверки входят в msa_infra_tests и регистрируются CTest. Команды конфигурации,
сборки и полного прогона остаются прежними, см. [README](../../README.md).
Отдельного запуска серверного окна, ручного порта и личных токенов не требуется.
Эти тесты проверяют настоящий процесс и локальные сокеты, но не настоящую модель,
публичных поставщиков данных, Tailscale, UI или качество ментора/памяти.
