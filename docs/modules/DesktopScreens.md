# Экраны ПК и параметры подключения

`src/ui/desktop/` содержит QML-модуль `Msa.Ui.Desktop 1.0` и C++-состояние
DesktopState. Он зависит от ui/common, core и Qt Quick, не от infra.
Расположение и параметры выбраны в решении 53.

QML-экраны находятся в `src/ui/desktop/UI/`; DesktopState — в
`src/ui/desktop/Model/include/msa/ui/DesktopState.h` и `Model/src/DesktopState.cpp`.
Разделение UI/Model следует решению 54 и не меняет зависимостей или QML URI.

## Точки входа и данные

`DesktopShell.qml` принимает обязательные свойства `client` (ClientModels) и
`desktop` (DesktopState). Слева меню четырёх разделов, сверху статус связи и
ошибки. Экраны остаются созданными при переходах, поэтому форма и текст ввода
не исчезают при открытии настроек. Все визуальные токены — в Theme.qml.

- ChatScreen: библиотека бесед, загруженные сообщения, следующая страница,
  создание беседы, отправка текста/команд с необязательным поиском и явный retry
  сохранённого User. Новый чат пользователь выбирает из обновлённого списка.
  Поле сообщения сохраняет текст после отправки, включая неизвестный исход;
  повторная отправка возможна только явным действием. Автоматического replay нет.
- PlansScreen: задачи с подтверждённой отметкой done, прогресс привычек,
  события сегодня и запрос событий выбранной ISO-даты.
- RemindersScreen: загруженные напоминания всех трёх видов, срок/место,
  период и доступный статус. Геолокация на ПК здесь не имитируется.
- SettingsScreen: host, port, скрытый token, autoConnect и результат сохранения.
  Форма работает без сервера. InputMethodHints помечает токен чувствительным вводом.

DesktopState проверяет диапазон навигации, форму и календарную дату.
ClientModels по-прежнему проверяет готовность сессии и типизированные действия.
`ClientListModel.detailsText` подготавливает подписи в C++: срок задачи,
количество привычки, сведения напоминания/события и автора сообщения.
Списки не очищаются при обрыве, показывают stale; ввод и просмотр остаются
локальными. Поля поиска/сообщения сами не запускают сеть.

## Файл настроек

`core/ClientPreferences.h` хранит параметры без Qt и валидирует заполненный набор.
`infra/JsonClientPreferences` читает/сохраняет конкретный файл без выбора пути.
Схема версии 1: `version`, `host`, `port`, `token`, `auto_connect`.
Неизвестные/пропущенные поля, неверные типы, пустые параметры и порт вне
1–65535 отклоняются. Максимум — 64 КиБ. Токен не обрезается и не попадает
в диагностику. QSaveFile заменяет файл атомарно; повреждённый файл сам не переписывается.

`apps/desktop/DesktopPreferencesController` выбирает стандартный путь
`QStandardPaths::AppConfigLocation/client.settings.json`, соединяет запрос
сохранения с infra и применяет в форму только успешно записанные значения.
Путь можно передать явно для тестов. Каталог создаётся приложением при сохранении.
Отсутствующий/повреждённый файл открывает настройки без сетевых попыток.
Пример — `client.settings.json.example`; настоящий файл исключён из git.

## Границы этого шага

Это библиотечные экраны и проверяемая связка настроек. main пока не создаёт
окно или клиентскую сессию: использование auto_connect при запуске и применение
нового endpoint относятся к сборке приложения. Сохранение настроек сеть не меняет.
Пять попыток и ручное восстановление реализованы ранее в TcpClient.

Формы задач/событий, привычек и напоминаний подключены через
[PlannerEditor](PlannerEditor.md). Изменение задачи сохраняет done/createdAt,
событие изменяет исходную серию; удаление требует подтверждения. Кнопки не меняют
списки до серверных данных и не повторяют запись после обрыва. Напоминание
по месту пока создаётся без выбора точки. Музыка — отдельный пункт.
Постоянного кэша предметных данных и Android-проверки пока нет.

## Проверки

`tests/infra/src/ClientPreferencesTest.cpp` проверяет отсутствие файла, строгую схему,
Unicode/точность токена, auto_connect=false, ошибки ввода/записи и сохранение
прежнего файла/состояния. Путь — временный, личные настройки не используются.
`DesktopScreensTest.cpp` проверяет навигацию, скрытый токен, сохранение формы,
календарную проверку и рендер всех четырёх экранов с последними данными без связи.
Запуск — через обычный CTest, offscreen, без видимого пользовательского окна.
Рендеры: `out/build/windows-debug-local/desktop-screen-0.png` … `desktop-screen-3.png`.
