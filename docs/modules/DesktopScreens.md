# Экраны ПК и параметры подключения

`src/ui/desktop/` содержит QML-модуль `Msa.Ui.Desktop 1.0` и C++-состояние
DesktopState. Он зависит от ui/common, core и Qt Quick, не от infra.
Проверка настроек делегирована общему ClientSettingsModel; внешний контракт
DesktopState и расположение настроек ПК сохранены. PlannerEditor находится в
ui/common, PlannerDialog ПК — оболочка общего PlannerFormDialog.
Параметры подключения выбраны в решении 53; навигация и оболочка — в решении 65.

QML-экраны находятся в `src/ui/desktop/UI/`; DesktopState — в
`src/ui/desktop/Model/include/msa/ui/DesktopState.h` и `Model/src/DesktopState.cpp`.
Разделение UI/Model следует решению 54 и не меняет зависимостей или QML URI.

## Точки входа и данные

`DesktopShell.qml` принимает обязательные свойства `client` (ClientModels) и
`desktop` (DesktopState). Слева меню «Сегодня / Планы / Тренировки / Музыка / Ассистент», настройки
закреплены внизу. Сверху статус связи и ошибки, снизу MusicPanel в компактном
режиме высотой 72 px. Полный режим находится в MusicScreen; оба представления
используют одну MusicModel из DesktopState.
Музыка не проверяет доступность сервера. Экраны остаются созданными при переходах, поэтому форма и текст ввода
не исчезают при открытии настроек. Все визуальные токены — в Theme.qml.
`DesktopWindow.qml` содержит системное окно и DesktopShell. Обязательные свойства
передаёт main через QQmlApplicationEngine; размеры и минимальный размер — в Theme.

- TodayScreen: местная дата устройства, приветствие и переход к планам.
  Дату готовит DesktopState и обновляет при смене дня; сервер для этого не нужен.
  Это минимальная стартовая страница без сводок и вымышленных данных.
- WorkoutsScreen: общий SportLibraryPanel, локальные поиск/фильтры/карточки и
  подтверждённые предпочтения через DesktopState.sport. Встроенные формы дают
  локальную цепочку программы → занятие → история/динамика. Подробнее —
  [библиотека](SportLibrary.md), [сценарий](SportJournal.md).
- MusicScreen: полный MusicPanel и AudioOutputSelector; последний также встроен
  в SettingsScreen и использует ту же AudioDevicesModel.
- ChatScreen: библиотека бесед, загруженные сообщения, следующая страница,
  создание беседы, отправка текста/команд с необязательным поиском и явный retry
  сохранённого User. Новый чат пользователь выбирает из обновлённого списка.
  Поле сообщения сохраняет текст после отправки, включая неизвестный исход;
  повторная отправка возможна только явным действием. Автоматического replay нет.
  Черновик находится в VoiceModel и редактируется без выбранной беседы/сервера.
  «Говорить», «Завершить запись» и «Отменить запись» управляют локальным C++-процессом;
  фраза добавляется в поле, а не отправляется. Статус/ошибка голоса отдельные.
  У сообщения есть явная кнопка «Озвучить»; «Остановить речь» находится у поля
  ввода. Загруженные сообщения озвучиваются и без связи; авточтения нет.
  В минимальном окне редактор может уменьшаться до высоты контрола; область
  сообщений сохраняет минимум двух контролов, кнопка озвучки находится в шапке сообщения.
  При высокой панели ошибки весь чат дополнительно прокручивается внутри
  оставшейся области; мини-плеер остаётся снаружи. Минимальная высота содержимого
  задана Theme.chatMinimumHeight, чтобы редактор и явный retry оставались достижимы.
  Во время записи виден уровень микрофона; пустой результат сопровождается диагностикой.
- PlansScreen: четыре внутренние вкладки «Задачи / Календарь / Привычки /
  Напоминания», отдельная прокрутка каждой. Существующие задачи с подтверждённой
  отметкой done, привычки и события сохранены; календарь запрашивает ISO-дату.
  Напоминания отображаются существующим RemindersScreen внутри вкладки.
- RemindersScreen: загруженные напоминания всех трёх видов, срок/место,
  период и доступный статус. Геолокация на ПК здесь не имитируется.
- SettingsScreen: host, port, скрытый token, autoConnect и результат сохранения.
  Форма работает без сервера. InputMethodHints помечает токен чувствительным вводом.
  Отдельная карточка выбирает папку модели Vosk и сохраняет voice.settings.json;
  выбор папки сам не включает микрофон.

DesktopState проверяет именованные Page/PlanSection, форму и календарную дату.
Тип зарегистрирован как несоздаваемый QML-тип: enum доступны по DesktopState,
но объект создаёт связка приложения. sections/planSections содержат только
описания меню; отдельной системы маршрутов нет. Page::Today — значение старта,
ошибка конфигурации переводит на Page::Settings. PlanSection сохраняется при
уходе с планов. Различные числовые позиции пунктов не используются как идентичность.
ClientModels по-прежнему проверяет готовность сессии и типизированные действия.
`ClientListModel.detailsText` подготавливает подписи в C++: срок задачи,
количество привычки, сведения напоминания/события и автора сообщения.
Списки не очищаются при обрыве, показывают stale; ввод и просмотр остаются
локальными. Поля поиска/сообщения сами не запускают сеть.

## Файл настроек

`core/ClientPreferences.h` хранит параметры без Qt и валидирует заполненный набор.
`infra/JsonClientPreferences` читает/сохраняет конкретный файл без выбора пути.
Схема версии 1: `version`, `host`, `port`, `token`, `auto_connect`.
Неизвестные/пропущенные поля, неверные типы, пустые параметры и порт вне
1–65535 отклоняются. Максимум — 64 КиБ. Токен не обрезается и не попадает
в диагностику. QSaveFile заменяет файл атомарно; повреждённый файл сам не переписывается.

`apps/desktop/DesktopPreferencesController` выбирает стандартный путь
`QStandardPaths::AppConfigLocation/client.settings.json`, соединяет запрос
сохранения с infra и применяет в форму только успешно записанные значения.
Путь можно передать явно для тестов. Каталог создаётся приложением при сохранении.
Отсутствующий/повреждённый файл открывает настройки без сетевых попыток.
Пример — `client.settings.json.example`; настоящий файл исключён из git.

## Границы этого шага

main создаёт окно и [DesktopRuntime](DesktopRuntime.md). При запуске параметры
загружаются, auto_connect включает ограниченный цикл. Сохранение сеть не меняет;
«Подключиться» применяет последний успешно сохранённый набор, а не черновик QML.
Переключатель auto_connect действует при следующем запуске. canConnect отключает
кнопку до появления корректного сохранённого набора. Смена endpoint очищает кэш
сервера, обычный обрыв его сохраняет. Пять попыток реализованы в TcpClient.

Формы задач/событий, привычек и напоминаний подключены через
[PlannerEditor](PlannerEditor.md). Изменение задачи сохраняет done/createdAt,
событие изменяет исходную серию; удаление требует подтверждения. Кнопки не меняют
списки до серверных данных и не повторяют запись после обрыва. Напоминание
по месту пока создаётся без выбора точки. [Музыка](MusicPlayer.md) подключена
в main и доступна без серверной сессии.
Постоянного кэша предметных данных и Android-проверки пока нет.

## Проверки

`tests/infra/src/ClientPreferencesTest.cpp` проверяет отсутствие файла, строгую схему,
Unicode/точность токена, auto_connect=false, ошибки ввода/записи и сохранение
прежнего файла/состояния. Путь — временный, личные настройки не используются.
`DesktopScreensTest.cpp` проверяет навигацию всех шести разделов, внутренние вкладки, сохранение черновика/поиска,
единый MusicModel, выбор выхода на обеих страницах, скрытый токен, формы,
календарную проверку и последние данные без связи. Проверяются 1000×720,
1280×800 и 1600×900, границы мини-плеера и кнопка отправки в чате.
Отдельно проверяются открытие/отмена формы из каждой вкладки без записи и
достижимость редактора/явного retry при высокой панели ошибки на 1000×720.
Запуск — через обычный CTest, offscreen, без видимого пользовательского окна.
Рендеры в `out/build/windows-debug-local/`: `desktop-screen-<раздел>.png`,
`desktop-<раздел>-<ширина>x<высота>-preview.png`, формы и голосовые состояния.
Идентификаторы разделов: today, plans, workouts, music, assistant, settings.

Спортивные экраны включают 22 карточки, P1/P3 как заготовки без дозировки,
просмотр истории при активном занятии и восстанавливаемые черновики исправлений.
Переход к исторической карточке и обратно проверяется в настоящей оболочке;
новые кадры sport-mvp-desktop-*.png сохраняются общими flow-тестами.
