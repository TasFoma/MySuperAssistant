# Выбор аудиоустройств и диагностика диктовки

Пользователь выбирает вход для Vosk и общий выход для музыки/озвучки в настройках.
Перечисление, сохранение и обновление устройств не открывают микрофон и не запускают звук.

## Точки входа

- `src/core/include/msa/core/AudioDeviceData.h`: каталог, устойчивые ID и выбранная пара.
- `src/infra/audio/include/msa/infra/AudioDevices.h`: QMediaDevices, изменения каталога,
  сохранение выбора и разрешение выходного устройства. `JsonAudioDevicePreferences.h`
  в том же каталоге содержит файловую границу.
- `src/ui/common/Model/include/msa/ui/AudioDevicesModel.h`: списки имён, индексы,
  команды выбора и обновления. Модель не зависит от infra и не перечисляет оборудование.
- `src/apps/desktop/include/msa/desktop/AudioDevicesController.h`: применяет каталог
  к UI, вход к ProcessSpeechRecognizer, выход к LocalMusicPlayer/QtSpeechSynthesizer.
- `SettingsScreen.qml`: два списка и обновление; `ChatScreen.qml`: индикатор уровня.

## Выбор и хранение

Пустой ID означает «По умолчанию», рядом отображается имя текущего устройства системы.
Явный выбор хранится по QAudioDevice::id в каноническом Base64. Совпадающие имена
не смешивают устройства. Недоступный сохранённый ID остаётся в списке с пометкой;
автоматической подмены другим устройством нет. Системный вариант можно выбрать всегда.
QMediaDevices сообщает об изменении каталога; также есть ручное обновление.

`audio.settings.json` версии 1 содержит только version, input_device, output_device.
Он расположен рядом с клиентскими настройками; DesktopRuntimeOptions.audioSettingsPath
позволяет передать другой путь. Пример — audio.settings.json.example. Предел файла
16 КиБ, ID — 4096 символов. Запись QSaveFile атомарная; ошибка не меняет выбор.
Повреждённый файл не переписывается при запуске/обновлении каталога. Старые файлы
voice.settings.json и music.settings.json не меняют схему и продолжают работать.

Изменение входа отменяет активную запись и завершает worker. Следующее «Говорить»
снова загружает модель с новым микрофоном. Выбор не начинает запись автоматически.
Изменение выхода меняет QAudioOutput музыки и останавливает текущую речь;
дальнейшая озвучка использует новый выход. Плейлист/позиция не сбрасываются,
автоматического возобновления остановленного звука нет.

Для системного выхода озвучка сохраняет штатный движок Qt. Для явного выхода на
Windows фабрика из `src/infra/platform/windows/src/WindowsSpeechEngine.cpp` выбирает
Qt WinRT с параметром audioDevice: SAPI не поддерживает этот параметр.
Новых пакетов нет, используется установленный Qt Speech. Если движок недоступен,
UI сообщает ошибку вместо чтения на другом устройстве. На других платформах
явный вывод озвучки пока отклоняется; Android остаётся отдельным этапом.
Документация Qt: [движки TextToSpeech](https://doc.qt.io/qt-6.5/qttexttospeech-engines.html).

## Диагностика

Worker захватывает PCM 16 кГц/mono/int16 с выбранного входа. Не чаще раза в 100 мс он выдаёт
пиковый уровень обработанного PCM, 0…1, без передачи звука в родительский процесс.
VoiceModel показывает уровень только во время записи и сбрасывает при завершении.
Нулевой уровень помогает заметить отсутствие сигнала, но сам по себе не определяет
причину: выключение микрофона, неверный вход, разрешения ОС или тишину.

При ручном завершении обрабатывается ограниченный остаток уже захваченного PCM
до FinalResult. Пустая фраза сопровождается пояснением и разрешает новую запись.
Движение уровня не гарантирует распознавания: язык/качество модели и речи проверяются
отдельно. Форматы других устройств пока не преобразуются; неподдерживаемый формат
возвращает ошибку. Индикатор не является тестом качества микрофона или разрешений Windows.

## Проверки

AudioDevicesTest.cpp проверяет JSON, повреждение/ошибки файла, отсутствующий ID,
дубликаты имён и перестановку каталога, отсутствие команд при применении снимка,
недоступный выход без скрытой подмены. SpeechRecognizerTest.cpp/FakeVoiceWorker.cpp
проверяют передачу выбранного микрофона, отмену при смене, уровни и пустой результат,
а VoiceModelTest.cpp — сброс индикатора. DesktopScreensTest.cpp проверяет выбор
клавиатурой и обновление без сервера; рендер audio-devices-preview.png.
Индикатор с ненулевым уровнем проверяется на снимке microphone-level-preview.png
с тестовым событием, без включения микрофона.

Автотесты не открывают микрофон и не воспроизводят речь. Они не проверяют слышимость,
фактическую маршрутизацию WinRT или распознавание личного голоса на модели пользователя.
Каталог настоящих устройств может перечисляться без запуска захвата/воспроизведения.
