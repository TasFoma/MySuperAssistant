# SqliteEventRepository

SQLite-реализация `core::EventRepository` по решениям 15, 24 и 40. Хранит
исходные серии событий; вхождения и повторы вычисляет CalendarService.
Заголовок — `src/infra/include/msa/infra/SqliteEventRepository.h`, реализация —
`src/infra/src/SqliteEventRepository.cpp`.

## Схема и точки входа

Конструктор принимает невладеющую ссылку на SqliteDatabase с полным списком
`sqliteMigrations()`. Владелец базы живёт дольше репозитория; работа — в его потоке
при живом QCoreApplication. Приложения пока не создают репозиторий.

Миграция 9 добавляет `events`: INTEGER PRIMARY KEY AUTOINCREMENT, полный заголовок,
обязательные год/месяц/день исходной даты, необязательные минуты от полуночи,
полное описание и повтор None/Daily/Weekly/Monthly (0/1/2/3 с CHECK).
SQL NULL означает отсутствие времени; 0 — допустимое 00:00. Прошедшие даты
разрешены, часовой пояс не преобразуется. Прежние таблицы не меняются.

`add` сохраняет копию с нулевым ID и назначает положительный ID.
`find` возвращает копию либо nullopt, `all` — независимые копии всех серий без
гарантии порядка. `update` заменяет все поля серии по ID, не создаёт запись
при отсутствии и возвращает false. `remove` удаляет серию, при отсутствии — false.
ID удалённых зафиксированных событий не используются повторно.

Параметры запросов сохраняют полный UTF-8 текст с пробелами, переносами и NUL.
Проверка непустого названия остаётся в EventService. Ненулевой ID нового события,
неверная дата, время вне 00:00–23:59 и неизвестный повтор — std::invalid_argument.
Ошибки SQL и некорректные сохранённые дата/время/повтор — std::runtime_error,
без маскировки отсутствием события или пустым календарём.

## Транзакции и ограничения

Каждая запись — один SQL-оператор, участвующий во внешней транзакции SqliteDatabase.
Сортировку и вычисление вхождений выполняет core. Отдельные вхождения не хранятся,
редактируется вся серия. Все события читаются целиком, постраничной загрузки нет.
Согласования конкурентных изменений нет; приложения пока не подключены.

Отметки предупреждений остаются независимыми в event_warning_marks, без внешнего
ключа на events и без автоматической очистки. Изменение времени не сбрасывает
отметку для прежнего ключа, удаление серии тоже её не удаляет. Миграция не
переназначает старые ID отметок. Импорта базы старого проекта нет.

## Тесты

`tests/infra/src/SqliteEventRepositoryTest.cpp`: шесть файловых тестов. Проверяются
обновление с версии 8 без потери задач, повторное открытие, постоянные ID, копии,
полные тексты с Unicode/NUL, все виды повторов, календарные границы, 00:00/23:59
и отсутствие времени, изменение/удаление, неверный ввод, SQL-ошибки и откат.
EventService и CalendarService проверяют сохранность исходной серии, перенос
31 января на 29 февраля и возвращение на 31 марта. EventWarningService проверяет
сохранность отметки при изменении времени, повторном открытии и удалении серии.
Команды — в [README](../../README.md).
