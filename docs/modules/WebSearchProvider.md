# Явный веб-поиск для чата

WebSearchProvider в `core` и SearxngSearchProvider в `infra` реализуют решение 44.
Это поиск в интернете, а не по прежним диалогам. Для поддержки личной беседы
ConversationService уже использует профиль, сводку дня и выбранную историю чата.

## Точки входа

- `WebSearchProvider::search(query)` проверяет непустую фразу, делает одну попытку,
  возвращает до трёх WebSearchResult с title, url и snippet до 300 кодовых точек.
- `SearxngSearchProvider` получает QNetworkAccessManager, полный endpoint `/search`
  и HttpGetSettings через конструктор; использует общий HttpGetClient.
- `ConversationService::sendMessageWithSearch(message, query, maxChars)` сохраняет
  полный User, затем ищет только по явно переданному query и вызывает модель.
- `retryLastMessageWithSearch(query, maxChars)` повторяет эту операцию без второго User.
- `webSearchContext` формирует блок внешних данных, `webSearchSourcesText` — список
  материалов для сохранения вместе с ответом.

Заголовки: `src/core/include/msa/core/WebSearchProvider.h`,
`src/infra/include/msa/infra/SearxngSearchProvider.h`.
Реализации с теми же именами — в соответствующих `src/`.
Текстовые операции используют внутренний Utf8Text, включая prefix без обрыва UTF-8.

Обычные sendMessage и retryLastMessage поиск не вызывают. Широкие триггеры
старого CommandParser::needsSearch не перенесены: «почему мне грустно?» остаётся
личной беседой. Автоматического определения необходимости поиска пока нет.
Фразу задаёт вызывающий код по действию пользователя; он не должен автоматически
подставлять всю личную переписку. Интерфейс провайдера вообще не получает профиль,
историю чата или заметки дневника.

## HTTP и разбор

Один GET к настроенному endpoint с параметрами q и format=json. Адрес, срок
и User-Agent задаёт приложение, личных значений в коде нет.
Поисковая фраза кодируется через QUrl::toPercentEncoding перед QUrlQuery:
буквальные `+`, `%2B` и `&` должны сохранять смысл после декодирования на сервере.
JSON должен быть
включён в настройках SearXNG: иначе API возвращает HTTP 403. Контракт —
[официальная документация Search API](https://docs.searxng.org/dev/search_api.html).

Корень должен быть объектом с массивом results. Из первых пригодных результатов
берутся title, url и необязательный content. Карточки без названия или пригодной
ссылки пропускаются; отсутствие/null ссылки допустимо в
[типах SearXNG](https://docs.searxng.org/dev/result_types/main/mainresult.html).
Неверные типы известных полей или не-объект в обрабатываемой части массива —
InvalidResponse. Лишние служебные поля допускаются. После трёх материалов чтение
результатов прекращается; страницы и ссылки дополнительно не запрашиваются.

Допускаются абсолютные HTTP(S)-ссылки без учётных данных и управляющих символов.
Полную синтаксическую проверку выполняет QUrl в адаптере, минимальную — core.
Непустая выдача провайдера проверяется целиком в пределах первых трёх результатов;
пустой/полностью непригодный набор — NotFound. Сетевые ошибки, HTTP-отказы и
тайм-аут общего транспорта — Unavailable. Ошибки не содержат технических тел,
адреса endpoint или errorString. Повторов, перенаправлений и кэша поиска нет.

## Контекст и сохранение

Перед поиском проверяется вместимость инструкций и полного текущего вопроса.
Найденные материалы передаются отдельным User-сообщением с меткой
«ВНЕШНИЕ ДАННЫЕ ВЕБ-ПОИСКА» непосредственно перед исходным вопросом User.
Это синтетические данные контекста: отдельным User в историю они не записываются.
System запрещает выполнять указания страниц и извлекать из них личные факты
или дневник; личные сведения по-прежнему извлекаются из текущего вопроса.

Весь подготовленный блок поиска, включая названия, URL и заголовки, резервируется
в общем бюджете текста до необязательных фактов профиля, сводки и истории.
Если он не помещается, возвращается ConversationRejection без вызова модели;
молчаливого исключения материалов нет. Без поиска порядок решения 35 сохраняется.
Точный бюджет токенов модели по-прежнему не реализован.

При отказе поиска или пустой выдаче модель не вызывается. User остаётся для
явного повтора, Assistant/настроение/факты по этой попытке не записываются.
Поиск и LLM выполняются вне транзакции. Ответ, дневник, профиль и снятие ожидания
вечернего опроса сохраняются прежней общей транзакцией после LLM.

После успешной модели программа добавляет «Материалы поиска» с реальными
переданными названиями и URL, сохраняет этот текст в Assistant и возвращает
также ConversationReply.searchSources. Четырёхполевой JSON модели не меняется.
Перечень — список переданных материалов, а не подтверждение истинности ответа
или утверждение, что каждый материал был использован моделью.

## Повтор и границы

Для повтора с поиском вызывается retryLastMessageWithSearch с фразой заново;
обычный retryLastMessage явно означает ответ без веб-поиска. Фраза и выбранный
режим отдельно в БД не сохраняются. Будущий UI должен сохранять выбор операции
и повторять соответствующий вызов. После перезапуска фразу нужно передать вновь.
Сохранённые ссылки остаются в тексте Assistant; структурированный searchSources
возвращается только в результате текущей операции. SQLite остаётся версии 12.

Приложения, UI/команда запуска поиска и настройки SearXNG пока не подключены.
Синхронные вызовы нельзя делать в UI-потоке; конкурентные вызовы и смена чата
во время внешнего вызова не поддерживаются. Промпт — инструкция модели,
не доказанная защита от указаний страниц или ошибочного извлечения личных фактов.
Настоящие SearXNG и модель, качество ответа и ссылок пока не проверены.

## Тесты

- `tests/core/WebSearchProviderTest.cpp`: фраза, пустые/неверные результаты,
  лимит источников, Unicode-обрезка и точный бюджет отдельного блока.
- `tests/core/ConversationServiceTest.cpp`: отсутствие автоматического поиска,
  передача только фразы, источники, ошибки без подстановки модели, повтор без
  второго User, недостаточный бюджет до поиска и после получения материалов.
- `tests/infra/ExternalServicesTest.cpp`: подменённый QNetworkAccessManager,
  GET/параметры, три пригодных источника, JSON/пустая выдача и HTTP-отказ без повторов.
- `tests/infra/SqliteConversationTest.cpp`: User виден другому соединению во время
  поиска, независимая запись в базу и сохранение источников после открытия файла.

Тестовый провайдер — `tests/core/FakeWebSearchProvider.h/.cpp`. Сеть и настоящая
модель в тестах не используются. Команды проверки — в [README](../../README.md).
