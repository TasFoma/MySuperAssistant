# SqliteReminderRepository

SQLite-реализация `core::ReminderRepository` по решениям 14–19, 25, 30 и 40.
Заголовок — `src/infra/include/msa/infra/SqliteReminderRepository.h`, реализация —
`src/infra/src/SqliteReminderRepository.cpp`.

## Схема и точки входа

Конструктор получает невладеющую ссылку на SqliteDatabase с полным списком
`sqliteMigrations()`. База живёт дольше репозитория; работа — в потоке владельца
при живом QCoreApplication. Приложения пока не подключены.

Миграция 10 добавляет одну таблицу `reminders` с INTEGER PRIMARY KEY AUTOINCREMENT
и общими ID для всех вариантов. Дискриминатор kind — Timed, Recurring или Place.
CHECK ограничивает набор допустимых полей:

- Timed: полный заголовок, местные секунды due_at и статус Pending/Fired/Missed (0/1/2);
- Recurring: заголовок, due_at и положительный интервал в минутах, без статуса;
- Place: заголовок, полный текст места, статус и необязательная пара координат.

Широта и долгота либо обе NULL, либо обе заданы в диапазонах −90…90 и −180…180.
Нули допустимы. Часовой пояс не преобразуется. Прежние таблицы не меняются.

`add` сохраняет копию с нулевым ID и назначает положительный ID.
`find` возвращает копию либо nullopt, `all` — независимые копии без гарантии порядка.
`update` заменяет запись целиком по ID, включая тип варианта; неиспользуемые поля
сбрасываются в NULL. Отсутствующая запись даёт false без вставки. `remove` удаляет
запись, при отсутствии — false. ID удалённых зафиксированных записей не используются повторно.

Тексты передаются параметрами запросов, сохраняются пробелы, переносы, Unicode,
встроенный NUL и длинные значения. Ненулевой ID новой записи, неизвестный статус,
неположительный интервал или некорректные/неконечные координаты вызывают
std::invalid_argument. Ошибки SQL и неверные сохранённые вид/статус/поля —
std::runtime_error, без маскировки отсутствием записи.

## Транзакции и ограничения

Каждая запись — один SQL-оператор, участвующий во внешней транзакции SqliteDatabase.
При откате восстанавливаются создание, смена вида, изменение и удаление.
Технические проверки репозитория не заменяют предметные правила: допустимость
прошлого времени при создании, проверку возможности расчёта следующего срока,
сортировку, расстояние и переходы статусов определяет ReminderService.
Чтение хранилища само не помечает пропущенные и не запускает напоминания.

Все записи читаются целиком. Автоочистки, импорта старой базы, таймера, геокодинга,
геолокации и доставки нет. ReminderService пока не объединяет обновления всех
записей одной проверки в транзакцию, поэтому при сбое возможно частичное обновление.
Гарантии доставки уведомлений при сбоях нет; конкурентные изменения не согласуются.

## Тесты

`tests/infra/SqliteReminderRepositoryTest.cpp`: восемь файловых тестов.
Проверяются обновление с версии 9 без потери событий, повторное открытие всех
вариантов и статусов, общие ID, длинные тексты с NUL, отрицательное время,
интервал, копии, координаты с нулями/границами/отсутствием, смена вида и удаление,
неверные данные, ограничения схемы, SQL-ошибки и откат.
ReminderService проверяет сохранение Missed/Fired и следующего dueAt между
открытиями, отсутствие повторного срабатывания, новое срабатывание по интервалу,
однократную геопроверку и сохранность места без координат.
Команды — в [README](../../README.md).
