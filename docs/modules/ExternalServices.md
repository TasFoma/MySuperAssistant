# HTTP-сервисы геокодинга, маршрутов и погоды

Реализации трёх интерфейсов `core` в `infra`, без прямого доступа к БД или UI.
Правила предметной области и текстовое представление находятся в
[NavigationService](NavigationService.md). Поведение согласовано решением 42.

## Точки входа

- `NominatimGeocoder` реализует Geocoder: полный endpoint `/search`, до десяти
  кандидатов на русском, полные display_name, координаты из строк Nominatim.
- `OsrmRoutePlanner` реализует RoutePlanner: три отдельных префикса
  `/route/v1/<профиль>` для Foot/Bike/Driving, первый маршрут, все legs/steps.
- `OpenMeteoWeatherProvider` реализует WeatherProvider: полный endpoint
  `/v1/forecast`, текущие показатели и прогноз текущего местного дня.
- `HttpGetClient` — общий транспорт этих адаптеров с HttpGetSettings.

Тот же транспорт используется SearxngSearchProvider для явного поиска чата;
его контракт описан отдельно в [WebSearchProvider](WebSearchProvider.md).

Заголовки: `src/infra/include/msa/infra/NominatimGeocoder.h`,
`OsrmRoutePlanner.h`, `OpenMeteoWeatherProvider.h`, `HttpGetClient.h`.
Реализации с теми же именами находятся в `src/infra/src/`.

Конструкторы получают внешний QNetworkAccessManager, адреса и HttpGetSettings
с положительным timeout и User-Agent приложения. Endpoint должны быть HTTP(S),
без userInfo, query и fragment. Конструктор отклоняет неверные параметры
через invalid_argument. Личных адресов и местоположения по умолчанию нет.
Тайм-ауты старого клиента (15/20/10 секунд) можно задать при сборке приложения;
в библиотеке они не выбраны за пользователя.

## Транспорт и выполнение

Нужен QCoreApplication. Менеджер, клиент и вызовы используют один рабочий поток
с диспетчером событий; менеджер должен пережить клиентов и запросы.
Контракт синхронный и использует локальный QEventLoop; из UI вызывать нельзя.
Связка должна исключать конкурентный и повторный вход в сервисы во время
обработки событий. Повторный вход в сам HttpGetClient возвращает Unavailable.

Каждая операция делает один GET с Accept=application/json и заданным User-Agent.
Перенаправления не выполняются. Только HTTP 200 без сетевой ошибки даёт тело;
HTTP-отказы, сетевые ошибки и общий тайм-аут возвращаются как Unavailable.
Тайм-аут включает получение тела, но не ожидание ограничения частоты Nominatim.
Незавершённый запрос прерывается. В ошибках нет URL, errorString и тела сервиса.
Повторов и логирования пользовательских адресов нет. Отмена пользователем
и ограничение размера ответа пока не реализованы.

## Nominatim

Параметры: q, format=json, limit=10, accept-language=ru. Каждый кандидат должен
иметь строковые lat/lon, корректные конечные координаты и непустой display_name.
Неверный кандидат отклоняет весь ответ; пустой массив становится NotFound в core.

Кандидаты, включая пустые списки, кэширует внешний
[CachedGeocoder](CachedGeocoder.md) в постоянном хранилище: семь дней для мест,
час для пустого результата. NominatimGeocoder собственного кэша больше не имеет.
Для ключа поставщика используется cacheSourceKey(), включающий endpoint и параметры.
После завершения или тайм-аута некэшированного запроса до следующего — минимум
одна секунда, по монотонным часам и точному Qt-таймеру. Это гарантирует интервал
между началами не меньше секунды и при задержке отправки внутри Qt.
Ограничение действует и после неудачного запроса.
Нужно создавать один геокодер на всё приложение и направлять через него все
запросы; разные экземпляры/процессы не разделяют ограничение частоты.

[Политика публичного Nominatim](https://operations.osmfoundation.org/policies/nominatim/)
требует ограничения общей частоты, идентификации приложения и отображения
атрибуции OpenStreetMap. Будущий UI должен показывать «© OpenStreetMap contributors»
со ссылкой на [условия](https://www.openstreetmap.org/copyright).
UI и фонового обхода нет. Точка геонапоминания назначается только по явному
подтверждению через PlaceReminderLocationService; постоянный кэш реализован
по решению 43.
Формат поиска — [официальное API](https://nominatim.org/release-docs/latest/api/Search/).

## OSRM

В выбранный префикс добавляются координаты longitude,latitude;longitude,latitude
с шестью знаками после точки, steps=true и overview=false. Конкретные профили
и адреса задаёт приложение; сервер должен действительно обслуживать нужный вид
передвижения. Пример отдельных серверов старого клиента — routed-foot/bike/car.

Проверяются code, непустые routes/legs/steps, числовые метры и секунды,
строки названий и манёвров, необязательный положительный целый номер съезда.
Сохраняются все манёвры всех участков первого маршрута. NoRoute/NoSegment
в успешном HTTP-ответе означают NotFound; неверные структуры — InvalidResponse.
HTTP-ошибки обрабатываются транспортом как Unavailable до разбора тела.
Длительность берётся из OSRM без «личной скорости». Локальную приблизительную
оценку при недоступности формирует core, а не HTTP-адаптер.
Контракт — [официальная документация OSRM](https://project-osrm.org/docs/v5.24.0/api/).

## Open-Meteo

Запрос содержит явные latitude/longitude, current=temperature_2m,
apparent_temperature,weather_code,wind_speed_10m; daily=temperature_2m_max,
temperature_2m_min,precipitation_probability_max; timezone=auto,
forecast_days=1, temperature_unit=celsius, wind_speed_unit=kmh.
Контракт — [официальная документация Open-Meteo](https://open-meteo.com/en/docs).

Текущие показатели обязательны и числовые. Пропущенные строки/числа не заменяются
нулём. Код WMO и вероятность осадков — целые. Если daily отсутствует, текущая
погода остаётся пригодной. Если daily передан, его time должен содержать одну дату,
совпадающую с датой current.time. Массивы переданных дневных значений должны
содержать ровно один элемент; null означает отсутствие данных. Экстремумы нужны
парой с минимумом не выше максимума. Осадки — от 0 до 100 процентов.

## Проверки и границы

`tests/infra/ExternalServicesTest.cpp`: QNetworkAccessManager подменён и возвращает
тестовый QNetworkReply без сокетов. Проверяются параметры и порядок координат,
профили OSRM, JSON и типы, отсутствие данных, кэш/частота, HTTP и сетевые ошибки,
тайм-аут, повторный вход и ошибки настроек. Только проверка интервала использует
реальные монотонные часы: один ожидаемый промежуток около секунды.

Настоящие публичные сервисы не вызывались. Приложения, настройки из файла,
протокол и атрибуция в UI пока не подключены. История расчётов, кэш и подтверждение
точки доступны на уровне библиотек. Текущая SQLite-схема — версия 12.
Команды проверки — в [README](../../README.md).
