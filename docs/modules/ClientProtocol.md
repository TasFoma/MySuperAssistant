# ClientProtocol

Граница JSON и данных клиентского представления в infra по решению 51.
Заголовок — `src/infra/include/msa/infra/ClientProtocol.h`, реализация —
`src/infra/src/ClientProtocol.cpp`; структуры без Qt — `core/ClientData.h`.
Связка и модели описаны в [ClientModels](ClientModels.md).

## Точки входа

- request(ClientReadRequest) кодирует снимок, библиотеку бесед, страницу сообщений,
  день/месяц календаря, профиль, дневник и историю маршрутов.
- request(ClientAction) кодирует завершённость задачи, создание беседы,
  полное сообщение, явный повтор с ожидаемым ID User/поисковой фразой и действия
  форм планировщика (ClientPlannerAction).
- decode строит полный ClientReadResult до передачи вызывающему коду.
- validateActionResult проверяет подтверждение исходного действия, включая
  адрес чата/задачи, ID, nullable данные и источники поиска.

Все операции чистые: не обращаются к сети/файлам/моделям и не изменяют вход.
Неверные данные вызывают invalid_argument без текста ответа или секретов.
Описание сигнатур и полей находится в Doxygen заголовков.

## Проверки и ограничения

Каждый вложенный объект разбирается в тип core с проверкой типов, затем сверяется
с сериализацией ProtocolPayload. Поэтому неизвестные/пропущенные поля и неявные
значения по умолчанию не принимаются. ID остаются каноническими строками int64
на проводе; при передаче в core используется точное целое. Текст не обрезается.
Даты/время/зоны, перечисления, координаты, nullable значения, дубли ID и размер
страницы проверяются до изменения представления.

Для страницы проверяются chat_id исходного запроса, порядок ID после курсора,
next_after_message_id и наличие продвижения при has_more. Для календаря ответ
должен соответствовать запрошенным дню/месяцу, дни месяца строго возрастают.
Статистика маршрутов хранит прогнозы без пересчёта клиентом.

Это адаптер уже реализованных чтений и действий моделей, не универсальный JSON-
интерфейс UI. Внутренний ClientPlannerProtocol кодирует создание/изменение задач
и событий, создание/отметки привычек, напоминания и удаление. Подтверждение update
обязано вернуть исходный ID, удаление — ровно deleted=true. Лишние поля отклоняются.
Проверки не заменяют предметных правил сервера. Кодек не создаёт интерфейсов в core
и не вводит зависимость ui/common от infra.

Тесты — `tests/infra/src/ClientModelsTest.cpp`: корректные данные, неправильные типы,
поля, ID/даты/enum, страницы, ссылки профиля, nullable/нулевые координаты и
подтверждения. При неверном подтверждении записи DesktopClientController сообщает
unknown и перечитывает данные после ручного восстановления, не повторяя действие.
