# LlmContextBuilder

`msa::core::LlmContextBuilder` собирает запрос к модели из готовых снимков данных.
Заголовок — `src/core/include/msa/core/LlmContextBuilder.h`, реализация —
`src/core/src/LlmContextBuilder.cpp`. Правила — решение 35.
API описан в Doxygen заголовков. Зависимостей от сети, Qt или хранилища нет.

## Точки входа и данные

- `build` принимает LlmContextInput и явный общий бюджет кодовых точек Unicode.
- `LlmContextInput` содержит системные инструкции, текущий вопрос, выбранные факты,
  готовый текст DailyContextService и сохранённые сообщения одного чата.
  Вызывающая сторона получает эти данные из сервисов и выбирает факты заранее
  через [UserProfileFactSelector](UserProfileFactSelector.md) или передаёт готовый список.
- `LlmMessage` и LlmRole (System/User/Assistant) в `LlmMessage.h` описывают сообщения
  запроса без HTTP/JSON и без сохранённых ID или времён.
- `LlmContext` содержит сообщения, использованный бюджет, число невключённых
  фактов и предшествующих сообщений и признак включения сводки.
- `LlmContextRejection` содержит причину отказа из-за ввода или общего бюджета.

## Порядок сборки

1. Проверить непустоту инструкций и вопроса; зарезервировать оба текста полностью.
2. Проверить историю: положительные уникальные ID, один чат, допустимые роли;
   упорядочить копию по ID. Если передан currentMessageId, проверить соответствие
   вопросу и исключить эту запись вместе с более поздними сообщениями.
3. Включать целые факты по переданному приоритету до первого непоместившегося.
   Более поздние факты не заменяют большой факт, порядок задаёт вызывающая сторона.
4. Включить непустую сводку дня целиком, если помещается вместе с заголовком.
5. На остаток бюджета отобрать непрерывную последнюю часть истории без обрезки
   сообщений. Если последнее предшествующее сообщение не помещается, история
   целиком остаётся за пределами запроса; обязательный вопрос всё равно включается.
6. Вернуть System (инструкции и включённые данные), историю User/Assistant
   от старых к новым и текущий вопрос User в конце.

Факты отделены заголовком «Факты профиля», сводка — «Сводка дня».
Заголовки появляются только при включении соответствующих данных и учитываются
в бюджете вместе с пробелами и переносами. Входные строки сохраняются полностью;
обрезка пробелов используется только для проверки непустоты. Бюджет расходуется
вычитанием, без суммирования длин с риском переполнения.

До сохранения текущего вопроса его не должно быть во входной истории. Если вопрос
уже записан, ID обязателен для надёжного исключения: по одному совпадению текста
невозможно отличить его от более раннего повторного вопроса. Сборщик ничего
не добавляет в историю и не удаляет из неё. Счётчик omittedHistoryMessages
учитывает только невключённые предшествующие сообщения, без текущего и более поздних.

ChatService::historyMessages остаётся отдельной операцией: он возвращает отказ,
если последнее сообщение не вмещается. В сборщике история необязательна, поэтому
это даёт успешный запрос без истории и соответствующий счётчик пропусков.

## Ограничения

Это бюджет текстов, а не токенов модели. Роли, шаблон чата, JSON, резерв ответа
и другие служебные части будущего запроса не учитываются. Числовой бюджет для
конкретных моделей ещё не выбран. При интеграции llama-server нужна точная проверка.

Сам сборщик не ищет факты; локальный отбор по словам и ручным тегам реализован
отдельно в UserProfileFactSelector. Автоматического назначения тегов, суммаризации,
переноса биографических событий из чата нет. MentorPrompt задаёт согласованные
инструкции; ConversationService передаёт их и остальные снимки в сборщик.
Сборщик принимает готовые снимки; не синхронизирует чтение разных сервисов
и не гарантирует свежесть переданных данных. Технические исключения текстовых
операций и выделения памяти не перехватываются. Приложения пока не вызывают сборщик.
Полезность приоритета памяти перед историей ещё не проверена на работающем чате.

## Тесты

`tests/core/LlmContextBuilderTest.cpp`: десять тестов обязательного бюджета,
Unicode и точных границ с учётом оформления, приоритета целых фактов и сводки,
непрерывности истории, ролей и порядка сообщений, нулевого/максимального бюджета,
невключённых частей, проверки ввода и исключения текущего вопроса по ID.
Интеграционный сценарий использует реальные ChatService, UserProfileService,
DailyContextService и тестовые часы/репозитории, проверяет неизменность данных
и повторяемость сборки. Файлов, сети и вызовов LLM нет.
Команды сборки и тестов — в [README](../../README.md).
