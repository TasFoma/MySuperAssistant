# SqliteEventWarningRepository

SQLite-реализация `core::EventWarningRepository` по решениям 26 и 40.
Сохраняет отметки подготовленных предупреждений между открытиями файла.
Заголовок — `src/infra/include/msa/infra/SqliteEventWarningRepository.h`,
реализация — `src/infra/src/SqliteEventWarningRepository.cpp`.

## Схема и точка входа

Конструктор принимает невладеющую ссылку на SqliteDatabase, открытую с полным
списком `sqliteMigrations()`. Владелец базы живёт дольше репозитория, все операции
выполняются в его потоке при живом QCoreApplication. Приложения пока не подключены.

Миграция 6 добавляет `event_warning_marks`. Первичный ключ — ID события,
год/месяц/день вхождения и вид предупреждения. Дата календарная, без часового
пояса, в диапазоне std::chrono::year. Вид хранится строкой BeforeStart, DayBefore
или OnDay с ограничением CHECK. Это дата самого события, а не дата выдачи.
ID хранится без внешнего ключа на таблицу events, добавленную миграцией 9:
отметки остаются независимыми и не очищаются при удалении серии. Источник
отметок — события CalendarService. Прежние таблицы миграция 6 не меняет.

`markIfNew` выполняет один подготовленный INSERT с обработкой конфликта только
первичного ключа. Возвращает true при вставке и false при повторе. Проверки
существования отдельным запросом нет. Разные события, даты и виды независимы;
изменение времени события не меняет ключ и не сбрасывает отметку.

Неположительный ID, неверная календарная дата и неизвестный вид отклоняются
через std::invalid_argument до записи. Ошибки SQL вызывают std::runtime_error,
не маскируясь повтором. Запись участвует во внешней транзакции SqliteDatabase;
откат позволяет снова сохранить ту же отметку как новую.

## Ограничения и тесты

Автоматической очистки отметок и импорта старой базы нет. Репозиторий не вычисляет
время предупреждения и не доставляет уведомления. Сохранение отметки означает
подготовку результата, а не подтверждённую доставку. EventWarningService пока
не объединяет все отметки одного checkDue в транзакцию, поэтому при ошибке
середины вызова часть отметок может остаться без возвращённого результата.

`tests/infra/SqliteEventWarningRepositoryTest.cpp`: шесть файловых тестов.
Проверяются переход с версии 5 без потери даты опроса, повторное открытие,
независимость всех частей ключа, 64-битный ID, календарные границы, неверный ввод,
откат/фиксация внешней транзакции и распространение SQL-ошибок. EventWarningService
с FakeClock не повторяет предупреждения после открытия базы заново и выдаёт
предупреждения нового вхождения ежедневного события.
Команды — в [README](../../README.md).
