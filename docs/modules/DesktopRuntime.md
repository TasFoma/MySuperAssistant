# Запуск desktop и владение сессией

DesktopRuntime соединяет уже перенесённые экраны, транспорт, постоянные
параметры, локальную музыку и голосовой ввод. Находится в apps/desktop; это связка приложения,
а не новый слой. Применение параметров выбрано решением 56.

## Точки входа

- `src/apps/desktop/src/main.cpp`: QGuiApplication, стабильные имена организации
  MySuperAssistant и приложения msa_desktop, CLI, runtime и QQmlApplicationEngine.
- `include/msa/desktop/DesktopRuntime.h`, `src/DesktopRuntime.cpp`: start/stop,
  стабильные models/state для QML, владение сетью и музыкальным плеером.
- `DesktopRuntimeOptions`: пути двух независимых файлов, seed очереди и сроки.
  По умолчанию подключение/auth — 10 с, запрос — 180 с, задержки — 1 с до 15 с.
  Долгий запрос допускает серверный LLM timeout 120 с из примера конфигурации.
  Дополнительные voiceSettingsPath/voiceWorkerPath позволяют временные пути в тестах;
  по умолчанию параметры голоса рядом с клиентским JSON, worker рядом с executable.
- `src/ui/desktop/UI/DesktopWindow.qml`: системное окно с DesktopShell, размерами
  из Theme и обязательными client/desktop. main импортирует оба статических
  плагина Msa.Ui.Common и Msa.Ui.Desktop.

## Запуск и закрытие

Конструктор runtime создаёт и связывает объекты без подключения и чтения
пользовательских настроек. После успешной загрузки QML main вызывает start.
Параметры подключения читаются через DesktopPreferencesController; отсутствие
или ошибка файла открывают настройки без сетевых попыток. Музыка восстанавливает
папку и громкость независимо от состояния сети и не начинает играть.

Если сохранены корректные параметры с auto_connect=true, начинается цикл из
максимум пяти попыток; при false транспорт до явного действия не создаётся.
Повторный start ничего не запускает. Закрытие последнего окна завершает цикл Qt;
aboutToQuit вызывает stop и отменяет сетевые повторы. Затем уничтожается QML,
runtime останавливает музыку и завершает поток сканера. Режима трея нет.
Ошибка загрузки окна или создания связки завершает процесс с кодом 1 и общей
диагностикой без токена или содержимого настроек.

Без CLI файлы выбираются в QStandardPaths::AppConfigLocation. Необязательные
`--config <path>` и `--music-config <path>` заменяют пути независимо; относительный
путь считается от рабочего каталога. Схемы файлов не менялись. Команды запуска
и пример первого подключения — в README.

## Явное подключение и смена сервера

«Сохранить» только атомарно записывает файл и обновляет сохранённое состояние UI.
«Подключиться» и ConnectionBanner используют последние успешно сохранённые
параметры; несохранённый текст QML не влияет на транспорт. auto_connect проверяется
только в start, поэтому сохранение включённого переключателя не начинает сеть.
Без корректного набора явное действие показывает настройки и не открывает сокет.

При прежних host/port/token runtime вызывает reconnect существующего клиента:
новый ограниченный цикл, последние строки и выбранный чат остаются в памяти.
При изменении любого из трёх полей старая связка закрывается, resetServerData
очищает списки/кэш/ID/выбор календаря, затем создаётся новый транспорт и контроллер.
Изменение только auto_connect не меняет принадлежность кэша серверу.
Музыкальная модель и плеер переживают замену сетевых объектов.

DesktopClientController передаёт предметные запросы и ответы. Ручное подключение
обрабатывает runtime, поэтому нет двух обработчиков, запускающих два цикла.
Перед удалением объектов вызывается DesktopClientController::stop: для ожидавшей
записи сообщается консервативный unknown и результат формы, затем закрывается
транспорт. Это необходимо, поскольку отложенные requestFailed транспорта могут
не выполниться после его уничтожения. Чтения отбрасываются, записи не повторяются.
При смене сервера предупреждение unknown остаётся, ID для retry прежнего User
не переносится. Повышение ревизий и уничтожение прежнего контроллера исключают
применение его поздних ответов к новой сессии.

## Проверки и ограничения

`tests/infra/src/DesktopRuntimeTest.cpp` запускается в msa_ui_tests с offscreen,
программным рендерингом и временными файлами. Проверяет первый запуск/повреждённый
файл, восстановление громкости без автозапуска, auto_connect=false, сохранение
без сети, ручное применение, смену сервера с ожидающей записью, unknown без
повтора, исчерпание попыток и отмену повторов при stop.

Проверяется настоящий msa_desktop отдельным offscreen-процессом: оба плагина,
загрузка окна, CLI и подключение к локальному управляемому TCP-серверу.
Отдельный тест открывает DesktopWindow с runtime, создаёт задачу через настоящий
процесс msa_server с временной SQLite-базой и проверяет сохранение строк после
остановки сервера. Внешняя сеть/LLM и личные настройки не используются.
DesktopScreensTest проверяет клавиатурную активацию новой кнопки подключения.
Рендеры: desktop-startup-preview.png, desktop-startup-invalid-preview.png,
desktop-runtime-preview.png в каталоге сборки. Команды сборки/CTest — в README.

Личный сервер/Tailscale, качество LLM, слышимость на реальном устройстве и Android
этими тестами не проверяются. Данные сервера кэшируются только в памяти процесса.
Формы напоминаний по месту пока не содержат выбора координат и атрибуции карты.

## Голосовой ввод

Runtime также владеет ProcessSpeechRecognizer и VoiceController. restore читает
voice.settings.json без запуска процесса, загрузки модели и открытия микрофона.
Worker запускается после «Говорить». Его путь по умолчанию — каталог приложения;
имя задаёт CMake по целевому executable. Параметры модели по умолчанию лежат рядом
с client.settings.json, что изолирует временные настройки тестов.

Смена сервера не меняет распознаватель или черновик. stop отменяет запись и
завершает worker до уничтожения моделей; VoiceController отписывает свой обработчик
перед уничтожением распознавателя. Голосовая ошибка не становится ошибкой сети.
Подробнее — [SpeechRecognizer](SpeechRecognizer.md).

QtSpeechSynthesizer и SpeechController принадлежат runtime; контроллер создаётся
до VoiceController, чтобы остановка синтеза выполнялась перед запуском записи.
Конструктор не создаёт движок Qt и не воспроизводит звук. stop останавливает речь,
контроллер отписывает обработчик до уничтожения backend. Смена сервера на озвучку
не влияет. Кнопки и ограничения — [SpeechSynthesizer](SpeechSynthesizer.md).
