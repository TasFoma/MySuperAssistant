## Черновик концепции для обсуждения

Главный сценарий: **выбрать программу → открыть тренировку → записать выполнение
→ завершить → увидеть сохранённый результат**. Это предложение, не утверждённый MVP.

| Область | Зачем нужна | Ограничение |
|---|---|---|
| Обзор спорта | Следующая/активная тренировка и точка продолжения | Только реальные данные, без вымышленных показателей |
| Программы | Готовые программы, просмотр состава, выбор; свои программы — обсудить | Источник содержимого и права на него ещё не выбраны |
| Упражнения | Описание и сведения, нужные для выполнения | Не выдумывать заполненный каталог и не загружать базы самостоятельно |
| Тренировка | Последовательный ввод выполненного и понятное завершение | Поля зависят от вида занятий; не назначать подходы/веса от имени пользователя |
| История | Завершённые занятия и просмотр записанного результата | Не создавать демонстрационную историю в рабочем приложении |
| Прогресс | Динамика по сохранённым занятиям | Метрики, формулы и периоды сначала согласовать; не рисовать пустые «0% успеха» |

Первым обсуждать одну законченную цепочку, а не одновременно весь фитнес-продукт.
Персональные рекомендации остаются будущим направлением: текущий ручной сценарий
не должен требовать Ламу. Шаги, датчики, часы, Health Connect, калории, XP,
награды и автоматический подбор нагрузки не добавлять в начальный объём молча.

Визуально: общая графитовая тема и лаванда, более выразительный спортивный
акцент через существующий Theme.progressAccent. Не делать отдельную тему,
неоновый интерфейс или новую систему Controls. Сначала переиспользовать
AppButton, AppIcon, SurfaceCard, SectionHeader, EmptyState, ErrorBanner,
ConnectionBanner и подходы существующих форм.
HabitProgress не превращать в модель тренировок: переиспользовать визуальный
приём допустимо, смешивать предметные сущности нельзя.

Desktop удобен для просмотра/редактирования программы; Mobile — для ввода
во время занятия. Предусмотреть разные компоновки, крупные действия и минимум
ввода на телефоне. Основную навигацию 1B/1C сохранить. Не делать одну длинную
страницу из всех разделов; способ внутреннего переключения выбрать после обсуждения.

Состояния для будущих макетов: нет программы/истории, есть данные, загрузка,
сервер недоступен/данные устарели, несохранённый ввод, сохранение ожидает ответа,
ошибка сохранения, успешное завершение. Обработать IME, Назад и уход с формы.
Не показывать работающую кнопку «Начать», пока сценарий за ней не реализован.
Макеты с условными примерами допустимы только вне рабочего приложения и с
явной пометкой «пример», без выдачи их за личные данные.
