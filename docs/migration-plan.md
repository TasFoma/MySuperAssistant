Описание старого проекта — `docs/old-project-overview.md`.

## Как работать с этим планом (для агента)

Один этап — один или несколько чатов. Каждый чат — один шаг этапа.

**В начале этапа или шага:**
1. Прочитать этот файл, AGENTS.md, docs/decisions.md, docs/lessons.md.
2. Найти первый невыполненный пункт.
3. Назвать, какие старые файлы нужны (только конкретные пути), и прочитать только их.
4. Показать план шага и задать вопросы по решениям, которых нет в docs/decisions.md. Код не писать, пока пользователь не ответит.

**В конце шага:**
1. Сборка проходит, все тесты зелёные.
2. Отметить выполненные пункты в этом файле (`[x]`).
3. Новые решения пользователя записать в `docs/decisions.md`, грабли — в `docs/lessons.md`.
4. Короткий отчёт: что сделано; что из старого кода сознательно не перенесено и почему;
   что стоит проверить руками; совет, что делать дальше; вопросы к следующему шагу.
5. Предложить сообщение коммита. Коммитит пользователь.

**Правила переноса:**
- Переносим поведение, а не код: старый код — источник требований, новый пишется по правилам.
- Если старое поведение похоже на баг — не переносить молча, а спросить.
- Логика переезжает с тестами. Если логика без тестов — сначала тест на старое поведение.
- Личные значения (IP, токены) не переносить в код (решение 7).
